# T10 G12K128 实机 Demo 设计

状态：设计稿，2026-09-10。尚未实现、构建或烧录；现有 hwframe-g12.hex 仍是 HWF2 硬件帧探针，不是本 Demo。

## 1. 目标和边界

在用户 STC32G12K128 上验证编译器生成 ISR 的实际保存/恢复行为。测试入口必须由 Clang `__attribute__((interrupt(N)))` 生成，经 LLVM 后端和支持 ISR 的链接器生成向量；禁止用手写保存37字节的汇编桩替代被测实现。少量汇编只属于前台寄存器哨兵、快照和测试辅助函数。

已知前提：HWF2 用户实测 Timer0 SP=01FE→0202→01FE，帧00 FF 74 02；这是当前配置的一次非嵌套测量。Demo 不把 INTR 配置位、PSW1各位恢复语义或其他中断源全部视为已验证。

实机 Demo 提供端到端、选定边界的寄存器与栈检查，不能代替 T10 的逐指令注入保存/恢复窗口、精确 RETI/IE/IP 时序验收。默认入口 fail-stop 另列，不通过改写默认处理器打印消息来制造 PASS。

## 2. 构建与文件结构

新目录建议为 `validation/mcs251-isr/realhw-demo/`：

- `main.c`：UART、命令解析、测试调度和不可变结果报告。
- `isr.c`：编译器生成的 Timer0(slot1) 和 Timer1(slot3) ISR。Timer0为低优先级，Timer1为高优先级。
- `helper.c`：独立翻译单元、noinline普通函数；ISR内ECALL调用，禁止LTO和内联消除。
- `sentinel.asm`：普通ABI函数，保存调用环境、建立独立寄存器哨兵、采样并恢复调用环境。不声明为ISR。
- `clobber.asm`：在被测ISR体内由C调用的普通ABI函数，只故意破坏调用约定允许破坏的寄存器。检查callee-saved寄存器覆盖应通过合法的高寄存器压力C代码实现，不使用违反ABI的helper制造误报。
- `link/build/check`：消费T09冻结工具及ISR CRT，校验向量、序言/尾声、helper调用、RAM布局、ELF→HEX与SHA256。
- `README.md / manifest.json / evidence/`：烧录操作、资产身份、用户实板记录。

首版O2硬件HEX，随后O0独立镜像作对照。工具链和CRT身份必须落manifest；若不能核实T09冻结身份，资产标记为开发验证，不能登记为正式T10冻结产品PASS。

## 3. 板级资源与内存

- ISP IRC=24MHz；UART1 P3.0/P3.1，115200/8N1，无流控；Timer2提供波特率，不用于中断测试。
- Timer0模式1单次溢出，每轮先停止/清TF0/装重载，再启动。ISR入口尽早停表，防止计数混入第二次自然溢出。
- 嵌套阶段用Timer1模式1，单独明确配置IP/IPH；寄存器地址与有效位须按G12手册确认，不照搬型号更大的芯片。
- G12 EDATA限于0000..0FFF。链接器显式预留全局数据、32字节寄存器快照、DPX/PSW快照、guard、正常C栈和独立测试栈；每段地址、容量、高水位由map检查，不手工假定C全局不会侵入保留区。
- 建议低地址0030..007F只放汇编可直接寻址的控制与快照；其余数据/guard/栈采用链接分配。固定地址若与链接分配混用，构建必须有区间重叠断言。
- 测量栈上下边界填充guard，不能把跨页硬件帧探针的32字节小窗口直接当作带C局部数组和嵌套ISR的可用栈。

## 4. 交互与报告

上电仅初始化并循环输出 `T10-G12 READY build=<id> commands=s,r,n,a`，不自动开测试中断。

- `s`：单次ISR测试。
- `r`：10000次单层测试。
- `n`：10000次受控两级嵌套测试。
- `a`：顺序执行s、r、n；前项失败立即停止。
- 任意测试完成后关闭测试中断，循环重发已保存的最终报告。再次执行必须显式收到新命令，清除旧计数和状态。

示例格式（协议设计，不是真实结果）：

```text
T10-G12 RUN case=repeat target=10000
T10-G12 RESULT case=repeat status=PASS completed=10000 irq0=10000
STATE reg=OK sp=OK guard=OK helper=OK shared=OK
```

首次失败保存：case、iteration、layer、字段名、expected/actual、before/after SP、ISR计数、helper结果、guard首个错误地址。失败后不再继续刷新或覆盖证据。

UART输出只在主程序、测试中断关闭时执行；绝不在ISR或嵌套窗口调用printf/串口函数。长测每100轮返回安全报告点输出进度，随后继续下一批，避免用户长时间无法区分死机和运行。

## 5. 测试S：单次编译器ISR与helper

1. 初始化全局payload、done、hit与共享测试字节，检查CRT初始化见证值。
2. 汇编前台哨兵函数保存C调用环境，在独立测试栈上建立R0..R31不同模式，设置DPX实际可见且合法的值；保存基线。不要给保留位赋予必须可保持的假值。
3. 以直接寻址写指令配置Timer0和IE，避免为装载SFR借用已建立的寄存器哨兵。
4. 等待循环只使用可直接寻址的标志位跳转、无寄存器变化的跳转与直接RAM倒计数。必须逐条核对等待指令对PSW/PSW1的影响；无法无扰动保存的标志不能标记为已覆盖。
5. Timer0硬件进入编译器生成ISR；ISR停表、增加hit，使用volatile固定局部数组及高寄存器压力代码，调用跨TU helper，设置共享byte/bit，最后设置done。
6. 回到哨兵函数，先无扰动保存待测寄存器及PSW/PSW1到独立快照，再用工作寄存器读取SP/DPX等。快照过程不得先借用A/DPTR再声称比较它们的原值。
7. 恢复C调用环境，关闭中断，比较所有纳入覆盖的字段。

PASS条件：恰好1次ISR、helper返回及副作用正确、寄存器逐项一致、SP恢复、guard完好、共享修改保留。PSW/PSW1只有在基线、等待和快照无污染经过机器码核验后才纳入PASS断言，否则明确NOT_TESTED。

helper输入由主程序在开中断前写入，全程保持不变；helper使用显式无符号整数运算（例如加法、异或与循环），主程序独立算出预期值，不在中断可能发生时调用同一个静态参数槽helper。不使用除法等隐式运行时libcall引入未审计重入路径。

## 6. 测试R：10000次单层

重复S的完整往返10000次，每轮重新置不同哨兵与运行时seed，验证精确hit和helper计数，以及每轮SP与guard。每轮单独检查，不能只比较最终SP或最终checksum；捕获首个失败轮次。累计计数至少32位，避免8/16位截断被误认为长测通过。

计数由主程序在中断关闭后读取，避免多字节读写撕裂。每轮等待有独立指令预算，未完成记TIMEOUT而非跳过或PASS。

## 7. 测试N：受控两级嵌套

Timer0 ISR在已经建立C固定帧、并完成一次helper调用后，调用普通ABI的低层哨兵函数。该函数保存低层当前环境，布置与主层不同的哨兵，然后启动高优先级Timer1，等待高层完成。

Timer1编译器ISR实际执行局部数组、不同helper计算与共享字节修改，不允许空ISR只推栈弹栈。高层使用独立helper/输入/结果存储，避免与被抢占低层共享静态参数槽。高层完成后停Timer1、写高层done并返回。

低层哨兵函数验证高→低的恢复，保存结果并恢复低ISR调用环境；低ISR继续执行后半段，再返回主程序，由主层哨兵验证低→主。以显式事件序列证明嵌套：LOW_ENTER、HIGH_ENTER、HIGH_EXIT、LOW_RESUME、MAIN_RESUME；仅两个hit都增加不能证明真的发生嵌套。

PASS要求两次恢复分别成功，高层确实改变过纳入测试的寄存器，共享修改贯穿两次RETI保留，guard完好、计数精确。10000轮逐轮检查。这里只验证一个受控ISR体内边界，不覆盖序言/尾声每条指令处的高优先级抢占。

## 8. 超时和异常策略

主层与低层等待均有限预算；能返回控制流的超时记录TIMEOUT并关闭定时器/中断。PC跑飞、损坏返回地址、死在ISR等无法保证靠软件循环恢复，界面表现可能为最后一条RUN/进度后无输出，不能宣称所有故障都会打印FAIL。

第一版不默认启用看门狗，避免复位抹除首次故障现场；若后续加WDT，需独立定义复位原因、保留RAM证据和有效性标记协议，不能只靠重启READY解释成测试通过。

## 9. 构建门禁与负向验证

发布前必须：

1. 核验编译器ISR入口不是手写普通函数，向量落正确槽，软件序言合计37字节且尾声逆序，最终RETI；helper为ECALL/ERET。
2. 确认局部数组真实分配、helper未内联、寄存器确实受压，测试没有被常量折叠成空操作。
3. 校验RAM区间、嵌套最大预算、guard、所有地址落G12物理范围。
4. QEMU使用当前机器正确加载接口（已核为-bios），通过串口交互验证正常路径和输出协议；硬件版TI轮询与QEMU test-port版必须分开标识。
5. 临时镜像故障注入至少包括：不触发IRQ→TIMEOUT、helper返回错误→FAIL、guard损坏→FAIL、删除/错配一个恢复操作→寄存器或SP检查失败。损坏PC造成无报告也必须作为失败/未完成处理。
6. 记录工具和固件SHA256、优化级别、map、反汇编/列表、检查结果；只有硬件版HEX对用户发布。

## 10. 台账映射

Demo证据可用于审核single-shot-timer、repeated-isr、integer-state-spx、helper-ecall-eret和controlled-two-level的覆盖程度；按实际字段逐项登记，不以总PASS自动放行全部T10。

- hw-frame-profile：引用已有HWF2实测，并保留PSW1语义未完全证明的边界。
- save-restore-windows：本Demo只覆盖选定边界，完整逐指令窗口仍NOT_RUN/另验。
- default-entry：另做独立镜像和外部观察设计，不能改变生产fail-stop语义。
- reti-ie-ip-timing：需另行硬件时序实验，不纳入本Demo PASS。

实现分阶段交付：先S与R硬件版并获得用户实测，再增加N；避免首次失败同时混入嵌套、优先级、helper和打印等多个未知因素。

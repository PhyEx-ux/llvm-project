# G12K128 Timer0 硬件中断帧实测 — 2026-09-10

## 来源与镜像

用户在本次会话中反馈 STC32G12K128 实板串口输出；以下保留一组完整采样行，去除串口助手缩进、时间戳和重复行。用户日志可见接收时间 00:04:39.599–00:04:40.036。不是代理直接操作硬件获得的数据。

对应本次交付 `hwframe-g12.hex`（v2，C 报告 + 独立汇编采样）：

```text

```

这是本地交付文件的校验值，未进行芯片 Flash 回读校验。固件要求 ISP IRC=24MHz，UART1 P3.0/P3.1、115200 8N1；用户先反馈持续 READY，再反馈发送命令后的采样报告。实际 ISP 选项未另附截图核验。

## 确认结论

1. **当前实板、当前配置下，Timer0 非嵌套中断的硬件帧大小为 4 字节。** 中断前 SP=01FE，ISR 入口 SP=0202，差值 4；ISR 入口采样之前没有 PUSH/CALL/ECALL，排除了编译器 ISR 软件序言的贡献。
2. **本次 RETI 后 SP 恢复正确。** R=01FE，与 B 相同；报告路径随后持续正常运行。
3. **SFR 85 作为 SPH 的读数符合真实跨页进位与恢复。** SPH:SP 为 01:FE → 02:02 → 01:FE。此结论是本次读数与栈行为一致，不扩展为所有 SPX 操作的完整验证。
4. **返回 PC 与链接地址吻合。** 栈内有效四字节从 01FF 开始，按地址升序为 `00 FF 74 02`；后三字节按高、低、中排列得到 FF0274，恰为交付 map 中 `_hwf_wait`。周围 28 个字节保持 A5，快照在 ISR 内复制，未被 C 打印调用覆盖。

| RAM 地址 | 值 | 解释 |
|---|---|---|
| 01FF | 00 | 与 PSW1 保存字节相符，具体语义仍需非零标志实验 |
| 0200 | FF | PC[23:16] |
| 0201 | 74 | PC[7:0] |
| 0202 | 02 | PC[15:8] |

## 不能据此宣称的结论

- 未读取 INTR 配置位；只能说帧大小与原先四字节假设一致，不能说直接测得 INTR=1。
- 第一帧字节为 00，尚不能单凭这一取值完全证明 PSW1 保存、恢复各位的语义。
- PSW1=02/00/00 不代表恢复失败。B 在启动定时器前采样，等待循环会改变标志；R 在返回侧循环检查完成后采样，都不是中断受理/RETI 完成瞬间的严格对照。
- BE_RAW=00/00/00 不能证明 BE 是 SPH；项目 STC32G 定义 BE 为 ADC_RESL，程序仅保留原始读数。
- 不覆盖其他中断源、优先级、嵌套、NMI、其他芯片或其他配置。
- 四字节硬件帧有实测依据，不等于编译器 37 字节 ISR 软件保存现场、T09/T10 或完整 ABI 资格已通过。

## 与旧版问题的关系

v1 仅上电输出一次，并在打印前执行中断路径，且打印调用会覆盖待读取的栈窗口。v2 改为持续 READY、g 触发、ISR 内复制快照、恢复 C 栈后重复报告。用户已实证 v2 的 UART 与测量流程可用；未对 v1 做单变量硬件实验，因此旧版无输出的具体根因仍不能定案。

QEMU 另行通过正常、超时、SP_MISMATCH 三条测试路径，但本页四字节结论来自用户实板输出，不以模型硬编码作为硬件证据。

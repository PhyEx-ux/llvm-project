作者：Alice，编译器架构设计负责人  
日期：2026-09-07  
版本：**v2**  
状态：**设计终稿，供 PM 落盘；不代表协议数字已冻结、功能已实现或验证已通过。独立复审结果为 APPROVE-WITH-NOTES，实施前注记 N1–N3 已纳入正文。**

## 用户裁定链记录

1. **支持优先级配置。**“所有中断同一个优先级肯定不行，要支持配置不同中断不同优先级。”首期必须支持不同数值优先级及受控的高优先级打断低优先级，撤销“全部同级／首期非嵌套”前提。
2. **不兼容 STC 官方库。**首期唯一语言入口为 `__attribute__((interrupt(N)))`；不提供 Keil `interrupt N`、官方 `stc.h`、官方 SFR 位名全集或 demo 原样编译承诺。
3. **采用三层配置面。**初始优先级进入统一编译／启动／链接契约；运行时优先级便利接口是后续可选设施；用户运行时接管后，必须明确静态抢占图及栈保证的失效边界，不得连带关闭其他安全检查。

本文只交付设计。标注“v2 修订”的章节包含本次优先级、嵌套及复审注记修订。证据索引见 §13，正文以 `[E编号]` 引用。

## 1. 总体裁定与证据校正

### 1.1 总体方案（v2 修订）

**已裁定（本次设计）**

采用以下首期架构：

> `interrupt(N)` 属性 → MCS251 专属 AST 语义及 ISR 调用约定 → 带槽号的 LLVM ISR 函数 → 每次入场完整上下文保存及 RETI → 链接阶段生成唯一完整向量表，并按数值优先级配置计算嵌套栈需求。

首期不是“给普通 C 函数末尾换一条 RETI”，也不是自动包装一个未经约束的普通 C 调用链。

安全边界同时包括：

1. ISR 入口具有独立于普通 Far24/Near16 函数的返回契约。
2. 保存异步被打断的直接下层现场；该下层既可能是主程序，也可能是另一 ISR 或其普通辅助函数。
3. 每个 ISR 的完整可达普通调用闭包不使用任何静态参数槽。
4. 支持按槽配置不同数值优先级，并受控支持严格高优先级抢占低优先级；首期固定 bank 0、DPS 0，不支持受保证运行期间改优先级、软件提升服务层级或 NMI。
5. 栈容量覆盖主程序预算与最坏优先级递增嵌套链；每层独立计入硬件帧、软件保存区、固定自身帧及普通调用链。
6. ISR 闭包安全与普通可抢占代码的 SPX 安全分别检查，不能以其中一项代替另一项。
7. 向量表、函数身份、安全摘要、优先级配置、启动初始化与栈预算形成编译—启动—链接闭环；缺项即拒绝。

“必须支持不同优先级”已经裁定，不再作为是否接受的开放问题。同级配置仍是合法特例，但不得将全部同级作为首期功能成立的必要条件。

### 1.2 必须纠正的先例表述（v2 修订）

**已裁定（本次设计）｜ARM 是函数属性先例，不是 interrupt CC 先例。**

本树 ARM CodeGen 调用的是 `Fn->addFnAttr("interrupt", Kind)`，并未在该路径设置一种名为 interrupt 的 LLVM calling convention。[E01]

真正可参考的“专属 ISR CC＋编号属性”先例是 MSP430：设置 `MSP430_INTR`，添加 `noinline` 和带编号的 `"interrupt"` 函数属性。[E02]

**已裁定（本次设计）｜t4 桩是受限成功样本，不是通用保存集。**

t4 交付桩保存 PSW/ACC/B/R0–R7，使用 ECALL 调普通 LLVM 函数，最后 RETI。源码明确提示 R8–R15 不在该保存范围内。[E07]

当前 LLVM 已可分配 R8/R9/R12–R15，并使用 WR/DR 值；DR16 是帧锚。因此不能将该桩原样推广为任意 C ISR。[E12][E13]

**已裁定（本次设计）｜区分“八槽”“IRQ 控制器容量”和“外设真实触发覆盖”。**

调查报告列出八个经典槽，但明确指出 ADC/LVD/PCA 无触发设备；有 transcript 的真实触发覆盖是 INT0、TF0、INT1、TF1、UART1 五路，历史优先级及嵌套尚未实测。[E17]

当前 QEMU 源树定义 64 个 IRQ 输入容量，但默认向量、IE/IP/IPH 配置同步及 STC32G 接线不能据此推导 64 路、甚至八路均可真实触发。[E18]

因此：

- 八槽映射可作为首期板级对接契约；
- 不得写“八路外设触发全部实测通过”；
- 当前 QEMU 源码、历史冻结二进制和真机结果分别记账；
- 历史 CRT 的八槽默认网不等于当前 QEMU CPU 的八路默认向量实现。

### 1.3 优先级与服务层级事实核对（v2 修订）

本节区分源码／文档事实与运行验证。源码核对不作 PASS。

#### 1.3.1 四档数值优先级

**已核源码事实；相关行为仍需 QEMU 实证／需真机实证。**

当前 QEMU 对 INT0、Timer0、INT1、Timer1、UART1 的普通优先级计算为：

`priority = 2 × IPH[对应位] + IP[对应位]`

因此档位为 **0、1、2、3，数字越大优先级越高**。[E18]

IP 与 IPH 是两个 8 位 SFR，当前地址分别为 `0xB8`、`0xB7`。每个源由一对位编码四档；寄存器宽度不代表存在八档优先级。

Intel 8XC251Sx 手册 §6.6 同样规定由 IPH0/IPL0 对应位编码四档。[E27] 原始经典 8051 只有两档，不应写成“经典 8051 固有四档”。本文讨论的是这里核对的 251／STC 扩展机制。

Intel 251 与 STC 派生型号的寄存器命名、有效位和外设映射不得无条件互换。

#### 1.3.2 高打断低；同级及低级被阻止

**已核源码事实；需 QEMU 实证／需真机实证。**

`mcs251_pick_interrupt` 排除 `level <= env->irq_level` 的请求；没有在服务中断时，以 `UINT32_MAX` 表示空闲，而不是一个用户可配置档位。

满足使能、pending 及其他受理条件时：

- 高于当前服务层级的请求可以抢占；
- 同级和更低级请求不能抢占；
- 多个候选请求中选择最高档；
- 当前 QEMU 对同档候选按 IRQ 扫描顺序选择。

该同档仲裁顺序不构成跨派生芯片的语言或 ABI 保证，也不用于证明不同 ISR 的共享内存独占。

入场路径没有自动清 EA。不能将“同级被屏蔽”描述为“全局中断自动关闭”。

#### 1.3.3 in-service 层级按嵌套保存和恢复

**已核源码事实；需 QEMU 实证／需真机实证。**

QEMU 使用：

- `irq_level`：当前服务优先级；
- `irq_depth`：服务层级栈深度；
- `irq_level_stack[]`：此前服务层级。

每次入场保存旧 `irq_level`，再设置新层级；RETI 弹出先前层级。高优先级 ISR 返回后，应回到仍在服务的低优先级层，而不是直接回到“无 ISR”。最外层 RETI 才恢复空闲状态。

`MCS251_MAX_IRQ_DEPTH=8` 只是模型内部数组容量，**不是八档优先级，也不是允许八层普通中断嵌套的证明**。当前入场代码在数组已满时没有完整的溢出拒绝机制，不能把该常量当安全门禁。

在普通档位仅为 0–3、配置固定、同级不抢占且没有 NMI 的条件下，同时在服务的普通 ISR 最多四层。模型通用配置 API 接受更大数值，不等于硬件或生产 ABI 支持这些数值。

服务层级数组是 QEMU 内部状态，不作为额外字节计入目标程序 RAM 栈。

#### 1.3.4 硬件帧与 NMI 边界

**已核源码事实；需 QEMU 实证／需真机实证。**

当前 `TARGET_MCS251` 路径使用四字节中断帧，入栈顺序为：

`PSW1、PC[23:16]、PC[7:0]、PC[15:8]`

RETI 逆向消费并恢复 PSW1。[E18]

这是本文首期硬件帧 profile。Intel 251 手册还存在由配置位选择不同中断帧的机制，不能把四字节帧无条件推广至所有 251 配置。[E27]

当前 QEMU 将已 armed 的 Timer0 mode3 请求特殊处理为内部 level 4，并存在绕过 EA／普通源使能检查的路径。[E18][E29]

**这个 4 不是可填入普通 `priority` 字段的第五档。**首期继续排除 T0 mode3 NMI 及其他不可屏蔽源。仅清 EA 不是排除该特殊路径的充分条件。

#### 1.3.5 寄存器声明、默认接线和可验证能力必须分开

**已核源码事实。**

当前 QEMU 的 IP/IPH 定义包含 PX0/PT0/PX1/PT1/PS/PADC/PLVD/PPCA 八个对应位段，但当前 STC32G 路径：

- CPU 默认向量初始化只覆盖 IRQ 0–4；
- IE/IP/IPH 到逐 IRQ 使能／优先级数组的默认同步只覆盖 IRQ 0–4；
- SoC 接线覆盖 INT0、Timer0、INT1、Timer1、UART1；
- ADC/LVD/PCA 位段声明不能证明其完整受理链已经接通；
- 64 个 IRQ 输入容量不能证明扩展源具有有效配置和外设触发能力。[E18]

准确口径为：

> 当前模型具备四档仲裁及嵌套服务层级机制；默认 STC32G 配置和接线可核对范围为 IRQ 0–4。八位寄存器声明与八路完整实现不是同一事实。

IE 的第 7 位是 EA，不能按“槽 N 一律对应 IE 位 N”生成使能代码。优先级位映射与源使能位映射必须分别描述。

本次核对的 STC32G 路径没有 IP2/IP2H、IP3/IP3H 的扩展优先级建模。扩展寄存器对可以作为未来板级数值描述的映射对象，但不进入当前 QEMU 可验证能力集合。

在其他机器／其他 SoC 文件中出现同名寄存器，不构成 STC32G 支持证据。

#### 1.3.6 one-instruction deferral 是当前模型的明确缺项

**已核文档事实。**

Intel 8XC251Sx 手册 §6.7.2.4 规定：指令执行未完成时不受理；RETI 或中断使能／优先级寄存器写入之后，至少再执行一条指令才向后续中断转移。[E27]

QEMU 文档明确声明这是非周期精确模型，**未建模 documented one-instruction interrupt deferral**；并明确列出其他定时器／UART 等外设不在当前机器范围内。[E30]

因此：

- 优先级比较、入场层级保存、RETI 层级恢复、指定模型指令边界的现场／栈恢复：**模型可验证，仍需实际探针**。
- RETI 或 IE/IP/IPH 写入后的硬件规定延迟、外设事件到真实受理点的周期／流水线时序：**当前模型不支持，待真机验证**。
- 模型允许在某指令边界受理，不证明真机在相同外设触发安排下也恰好在该边界受理。
- 模型缺项不记 PASS，不因调整期望输出而变成 PASS；也不误记为被测 ISR 功能失败。

Intel 251 手册要求与 STC 派生硬件行为分别登记。ISR 保存与栈安全设计不得依赖该延迟才成立。

## 2. 范围切分

### 2.1 首期最小可用范围（v2 修订）

**已裁定（本次设计）**

| 项目 | 首期边界 |
|---|---|
| 语言入口 | 唯一入口为 C 函数 `__attribute__((interrupt(N)))` |
| ISR 签名 | 有原型的 `void f(void)` |
| 注册 | 一个 ISR 定义注册一个槽；首期标准板配置八槽 |
| 入口方式 | 硬件中断 → 向量 EJMP → ISR；不产生普通调用帧 |
| 返回 | 独立 RETI |
| 现场保护 | 每次入场固定完整整数上下文保存，不做按需删减 |
| ISR 内调用 | 可见、可闭合审计的直接普通调用；首期限定 Far24／ECALL-ERET |
| 参数纪律 | 每个 ISR 的整条可达路径不得分配、读写静态参数槽 |
| 调用链限制 | 无递归、无间接调用、无未知外部函数、无未经认证的运行库调用 |
| 寄存器组 | 中断开放期间固定 bank 0、DPS 0；不提供 `__using` |
| 初始优先级 | 每槽显式数值，进入统一编译／启动／链接契约；基线普通档位为 0–3 |
| 中断嵌套 | 受控支持严格高优先级抢占低优先级；同级和更低级不得抢占 |
| 配置生效 | CRT／启动代码按最终数值描述初始化；受保证运行期间优先级固定 |
| 运行时重配置 | 不属于首期固定配置保证；可选便利接口后续设计 |
| ISR 栈 | 调用闭包仅固定大小帧；按最坏优先级递增链计算 headroom |
| 普通代码 SPX | ISR-enabled 工程所有最终保留的普通可执行代码也须提供合格安全摘要 |
| 对象与链接 | 新生产功能走 ELF 链及显式协议；历史 REL 用例保留为参考 |
| 官方库兼容 | STC 官方语法、头文件、宏名及 demo 原样编译不属于首期目标 |

“可闭合审计”首期具体指：ISR 根及普通辅助函数定义位于同一 LLVM 模块，辅助函数具有本地绑定，每条普通调用边可解析。

不同 ISR 可以分别位于不同模块；最终链接结合各根安全／栈摘要与板级优先级配置计算嵌套需求。槽号唯一性由最终链接检查。

允许主程序、不同优先级 ISR 共享**不使用静态槽、且满足异步重入要求**的普通辅助函数。不要求机械复制所有函数。

### 2.2 明确不包含（v2 修订）

**已裁定（本次设计）**

首期不包含：

- 原生 SDCC `__interrupt(N)`、Keil 后缀 `interrupt N` 或其他裸 `interrupt` 关键字入口。
- `interrupt(N, P)` 双参数属性。
- `__using(N)`、自动分配 bank、bank 1–3 调用桥。
- 基于优先级独占寄存器的保存优化、按需保存优化。
- 受保证运行期间调整优先级、软件优先级提升、手工操纵 in-service 层级、同级递归再入。
- NMI ISR、T0 mode3 NMI，以及超出已认证普通优先级机制的入口。
- 自动保存／复制 OSEG 或 `_PARM_n`。
- 自动把 ISR 调用链改为栈传参。
- 任意跨 TU 调用闭包、任意函数指针调用。
- ISR 路径的 VLA、动态 alloca、stackrestore、setjmp/longjmp。
- 裸 ISR、手工返回指令混入 C ISR、异常展开。
- 自动清除各外设中断标志。
- STC 官方 `stc.h`、SFR 位名全集、必须同名同形提供的优先级宏族、官方 demo 原样编译。
- 因板级描述登记更多中断源而宣称相应外设已受支持。

**普通的高打断低嵌套已经包含在首期，不属于“嵌套优化”排除项。**

用户移植官方 demo 时，需要把 ISR 声明改写为本设计属性形态，并满足 `void f(void)` 等语义限制。声明的机械改写不保证整个 demo 已满足调用闭包、静态槽、SPX 或栈容量规则。

后续功能必须分别扩展 ABI、分析与测试，不能通过一个“允许不安全 ISR”开关解除全部限制。

## 3. Sema 与前端设计

### 3.1 修复假接受

**已裁定（本次设计）**

当前 `handleInterruptAttr` 对 mcs251 没有显式分发，落入 ARM 默认分支；SemaARM 可以添加 ARMInterruptAttr，但 MCS251 没有对应目标 CodeGen 消费路径。[E03]

分两步修复：

1. **封堵阶段**：增加 mcs251 显式分支；在完整 lowering 尚未接通时，对该目标明确报“不支持”，不再挂 ARMInterruptAttr。
2. **功能阶段**：引入目标专属 `MCS251InterruptAttr`，使用共用 `Interrupt` ParseKind 分发，进入 MCS251 专属检查及 CodeGen。

不得以 `-Wno-attributes`、删除属性或产生普通 ERET 函数作为降级方式。

### 3.2 语法与约束（v2 修订）

**已裁定（本次设计）**

首期规范示例：

```c
void timer0_isr(void) __attribute__((interrupt(1)));
```

检查规则：

- 恰好一个整数常量表达式参数。
- 截断前检查非负及协议数值范围。
- 编号表示**逻辑向量槽序号**，不是 IE 位号、优先级或绝对地址。
- 必须为有原型、非变参、返回 void、无参数的 C 函数。
- 声明／定义的 ISR 身份和编号一致。
- 同 TU 同槽冲突立即报错，跨对象由链接器报错。
- 属性必须在首次声明建立 ISR 身份。
- 禁止普通 C 调用 ISR、ISR 普通调用另一 ISR、取 ISR 地址、显式转换逃逸。
- 拒绝 naked、always_inline、不兼容 CC、alias、ifunc、weak、COMDAT 组合。
- ISR 不做入口内联。
- `interrupt(N,P)` 按属性参数数量错误拒绝，不忽略第二参数。

**已裁定（本次设计）｜编号范围分两层。**

Sema 检查整数表示合法性；板级向量描述存在时可提前检查可注册性；最终链接按实际数值化板级描述再查。

`N>7` 不是 MCS251 ISA 层永久非法；在首期八槽配置中是非法注册。

### 3.3 方言与红线（v2 修订）

**已裁定（本次设计）**

SDCC 的 lexer 确有 `__interrupt`、`__using`，语法分析支持编号表达式，向量生成器按编号表发射 EJMP；寄存器组数为四。[E04][E05]

首期不新增这些关键字，优先稳定属性语义与 ABI。Keil `interrupt N` 与 SDCC `__interrupt(N)` 不是同一种拼写，两者均不在首期范围。

这不是因为 E.5 禁止语言关键字。E.5 禁止的是型号／模式字符串驱动目标语义、按函数名选指令、编译器读取板 Makefile 等行为；稳定语言拼写和目标属性名称并不等同于型号分派。[E16]

后续若支持 `__interrupt(N)`，它只能是同一 AST 属性及数值槽号契约的另一入口，不得建立第二套 lowering。构建层兼容宏不得被宣传为“完整 SDCC ISR 方言兼容”。

STC 官方库兼容明确不在本次目标内；不新增相应语言、头文件或宏名承诺。

### 3.4 初始优先级配置选择（v2 修订）

**已裁定（本次设计）｜采用单参数属性与唯一数值槽描述。**

| 方案 | 优点 | 主要代价 | 裁定 |
|---|---|---|---|
| `interrupt(N, P)` | 优先级意图紧邻函数定义；Sema 可检查 P | 优先级仍须汇总给 CRT 和链接器；增加声明合并、板级冲突和覆盖规则；将应用调度选择绑定到源定义 | 首期不采用 |
| `interrupt(N)`＋板级／构建层每槽 `priority` | 初始配置只有一个来源；启动寄存器值、抢占图、栈预算一致；同一 ISR 可按应用选择复用 | 需要工具清楚展示槽→ISR→priority 的最终绑定 | **采用** |

“优先级跟函数写在一起”具有就地可读性优势，但不能代替全系统配置一致性。本期以最终链接绑定和配置指纹解决失配，不引入第二个可生效来源。

两种方案均可使用纯数值契约，均不违反 E.5。当前选择不是因为 E.5 禁止属性第二参数。

“进入编译器可见契约”在本方案中表示：

1. 所有相关编译单元采用一致的 ISR-enabled 安全检查契约。
2. 数值槽描述具有确定版本与配置身份，编译记录、CRT 和链接输入必须一致。
3. 最终链接解析 ISR 注册，将函数与唯一的每槽优先级绑定。
4. 需要提前检查时，前端／驱动只接收规范化数值输入，不读取板 Makefile、不按型号分派。

编译器无需按优先级生成不同保存序言。首期对所有档位使用同一完整保存规则。

初始优先级可以由板能力与应用选择合成，但合成后必须只有一个确定值；它不是不可覆盖的器件名称推断。

初始化 IP/IPH 的责任属于 CRT／启动代码。运行时操作与责任边界见 §9.5。

## 4. IR、调用约定与对象身份

### 4.1 路线比较

**已裁定（本次设计）**

| 路线 | 优点 | 主要问题 | 裁定 |
|---|---|---|---|
| ARM 式，仅函数属性 | 改动面小，有现成目标先例 | 普通 CC 仍可流入调用点；字符串标记可能被不支持的消费者忽略 | 不作为最终方案 |
| MCS251 ISR 专属 CC＋编号属性 | 将硬件入口身份与普通函数区分；适合拒绝调用与返回帧错配 | 需修改 Clang 类型／CC、LLVM CC 登记及验证链 | **采用** |

这与 DESIGN C.3 一致：返回帧是函数 ABI，仅用非类型化字符串不足以保护调用身份。[E14]

### 4.2 表示路径

**已裁定（本次设计）**

新增目标专属 ISR CC，工作名称 `MCS251_INTR`，文本拼写建议 `mcs251_intrcc`。其含义是“只能由匹配的硬件中断入口进入”，不是“普通函数但保存较多寄存器”。

完整路径：

Clang AST 保留 ISR 属性及函数类型上的目标 CC → 重声明／使用／转换检查 → CodeGen 设置 LLVM CC＋编号属性，例如 `"mcs251-isr-vector"="1"`，入口统一解析整数 → 目标 verifier 检查 CC 与编号成对、类型合法、禁止用途 → MachineFunction 保存入口类型／槽号／保存方案／栈信息 → MC／对象输出逐函数身份及槽注册记录 → 最终链接确认槽目标确为 ISR 入口。

LLVM CC 存于 Function 和 CallBase，已有文本和 bitcode 序列化路径；opaque pointer 自身不携带调用身份。[E20]

**仍开放｜数字登记。**

`MCS251_INTR` 的 LLVM 数值 ID、Clang CC 枚举登记、对象入口种类及能力位数值须统一登记，不能复用 ARM/MSP430 数字或自行占用候选值。

### 4.3 防止优化和错误调用绕过

**已裁定（本次设计）**

- ISR CC 列为不可普通调用的 CC；同时检查“普通 CC call 指向 ISR 定义”的错误，不能只检查 call 自身 CC。
- 禁止以 `preserve_allcc` 替代 ISR CC：它没有 RETI 和硬件帧语义。
- ISR 入口不得被 IPO 改成 `fastcc`，不得被合并成普通函数入口。
- ISR 注册必须在 IR 优化阶段构成真实保活根；仅生成最后阶段才出现的对象符号不足以防 GlobalDCE。
- 链接 GC 必须把已注册 ISR 作为根；`noinline` 不等于保活。
- 普通辅助函数不传播 ISR CC，仍按普通调用 ABI 使用 ECALL/ERET。
- 首期维持禁止尾调用优化；绝不允许尾跳辅助函数绕过 ISR 恢复及 RETI。
- 手写 IR 也必须经过目标 verifier；不能绕过 Sema 后得到静默普通返回。

已知源码引用、转换和对象调用边必须拒绝；任意手写汇编或伪造整数地址跳入 ISR 属于受支持 C 契约之外。

### 4.4 对象协议边界（v2 修订）

**已裁定（本次设计）**

至少需要承载：协议版本及必须理解的 ISR 能力、函数符号关联、ISR 入口种类和硬件帧 profile、槽号、保活信息、安全摘要和固定栈摘要。

若使用带符号 relocation 的专属记录 section，应与 `.mcs251.attributes` 分离；后者现有设计明确禁止属性字节 relocation。[E21]

#### 独立安全摘要

对象协议必须区分以下信息，不能合并成一个模糊的“ISR-safe”标志：

| 信息类别 | 含义 |
|---|---|
| ISR 入口身份 | 专属 ISR CC、槽注册及硬件帧 profile |
| ISR 闭包安全摘要 | 整个普通辅助闭包无静态槽、无未知调用、无动态帧，调用入口符合首期要求 |
| 可抢占 SPX 安全摘要 | 本函数／代码片段不存在未认证动态或分字节 SPX 更新，以及其他未认证栈状态修改 |
| 固定栈摘要 | 最终机器代码自身固定开销上界、普通调用边及返回帧契约、未知需求标志 |
| 初始化／配置关联 | 与最终数值优先级描述、启动资产及安全检查协议的关联 |

ISR 闭包安全不能证明另一 TU 的普通函数不存在 VLA。

反之，普通代码通过 SPX 检查也不说明它没有静态参数槽：静态槽禁令针对 ISR 闭包，不能误扩展成所有普通函数都必须使用无槽 ABI。

摘要必须绑定最终实际函数／代码及协议版本。优化、LTO、晚期展开产生新行为时须重新检查，不能沿用旧证明。

逐 ISR 根的摘要必须足以计算单根完整开销上界，包括硬件帧 profile、保存方案、固定自身帧和普通调用链。不得将“已知栈开销下界”当成“完整上界”用于嵌套容量验收。

缺少可抢占 SPX 安全信息的旧对象、手写汇编或运行库代码，在 ISR-enabled 生产链接中不得按“没有报错”视作安全。

#### 优先级绑定

优先级由最终槽描述绑定，不在函数属性与板级描述中各保留一个可独立生效的来源。改变优先级必须使启动初始化、抢占图、headroom 和最终配置指纹重新一致。

#### 默认 fail-stop 入口身份

默认终止处理器必须具有专门的、可核验的**不可返回 IRQ 终止入口身份**，并绑定配套 CRT 资产和入口开销。它不是普通 C ISR，也不是任意普通 C 函数。

- 用户注册记录仍只能指向合法 ISR 入口。
- 默认入口只允许由链接器为未注册槽选择。
- 不能凭保留符号名、`noreturn` 属性或用户改名获得默认入口豁免。
- 任意普通函数、用户伪造同名符号、错误版本资产均不能成为合法默认目标。
- 其身份及选用规则与 O2/O4 同时落地，不能先交付基于函数名的临时旁路。

**仍开放｜逐函数记录线格式。**

推荐并入正在冻结的函数入口／site 协议，另设必要的向量注册记录；不新造与其矛盾的函数身份系统。字段编号、记录大小、上界有效性、关联方式和默认终止入口表示冻结前，不得宣称完整对象 ABI 已可交付。

新生产路径采用 ELF；历史 REL/Python 链不扩为第二套 ISR 协议。[E21]

## 5. 保存集与 ISR 序言／尾声

### 5.1 从 SDCC 学习什么

**已裁定（本次设计）**

SDCC 的实际机制并非简单“总是保存 acc/b/dpl/dph”：

- ISR 序言还保存 DPXL、DR20/24/28，并处理固定字节寄存器；
- bank 0 叶 ISR 可按使用保存；
- bank 0 非叶 ISR 保全 bank、退出保存优化；
- 其他非叶 ISR 保守认为 A/B/DPH/DPL/条件状态被调用方修改；
- 非零 bank 依赖独占性，调用其他 bank 时还要保存目标 bank。[E06]

尤其不能复制 SDCC 关于“DR16 仅启动时使用”的省略理由：本 LLVM 后端在正常 C 动态帧中使用 DR16。[E12]

首期采用固定完整保存。后续按需保存必须在最终物理寄存器使用、晚期展开、隐式 clobber 和完整调用闭包上证明。

### 5.2 首期完整整数上下文（v2 修订）

**已裁定（本次设计）｜37B 是每层保存量，不是整个中断系统只保存一次。**

| 物理集合 | 每层软件保存字节数 | 覆盖内容 |
|---|---:|---|
| DR0、DR4、DR8、DR12 | 16 | bank 0 的 R0–R7、R8/R9、B/ACC、R12–R15 |
| DR16、DR20、DR24、DR28 | 16 | 帧锚及扩展固定临时寄存器 |
| 当前选中的 DPX/DR56 | 4 | 包含 DPL/DPH/DPXL 的完整保存槽 |
| PSW | 1 | 经典状态，包括不完全由 PSW1 覆盖的状态 |
| **合计 `P_save`** | **37** | 不包含硬件中断帧和普通帧 |

WR 是同一物理字节集合的别名，不另加保存；A/B 由 DR8 覆盖；DPL/DPH 由 DPX 覆盖。

PC、PSW1 由首期四字节硬件帧及 RETI 恢复。SPX/DR60 不 push/pop，依靠合法栈操作及严格平衡恢复。不保存无编码的 DR32–DR52。

#### 嵌套后的完整性论证

完整性目标不是“最终恢复主程序寄存器”，而是：

> 每次 ISR 返回，都恢复它直接打断的那一层在受理边界的整数状态与 SPX，并继续该层原来的指令流。

主程序、低优先级 ISR 及其普通辅助函数使用同一批物理整数寄存器。下层变成 ISR，不会增加另一批必须保存的 WR/DR 存储。

因此，在固定 bank／DPS、既定整数寄存器使用范围、合法四字节硬件帧和完整保存编码成立时，**每层仍为 37B，无须仅因嵌套增加一种寄存器类别**。

但各层必须在目标栈上拥有独立保存区。两层是 `2×37B` 软件保存，四层是 `4×37B`；硬件帧和普通帧另计。

这不是“所有设备状态都可重入”的承诺。共享内存、外设事务、定时解锁状态及其他系统控制状态仍受 §5.3、§7 约束。

#### 保存／恢复中途的混合现场

下层保存到一半时，部分寄存器已备份、部分尚未备份；下层恢复到一半时，部分寄存器已经恢复、部分仍为 ISR 值。

高层应保存并恢复**这个实际混合状态**，不能试图把它提前转换为主程序状态。

成立条件：

1. 下层尚未保存的值不得先被下层序言破坏。
2. 已入栈且仍存活的下层保存区始终位于当前 SPX 所保护的范围内。
3. 高层只在当前 SPX 以上建立自身栈区，退出时精确返回该 SPX。
4. 下层弹出的栈字节不再被下层后续指令依赖；高层可以使用已经释放的空间。
5. 指令级保存／恢复的物理别名、隐式 clobber 和受理边界经过验证。

这允许高层打断尚未完成的下层序言或尾声，不要求整个序言／尾声全局关中断。

LLVM 当前未建模的 A/B、DPTR/DPX 别名关系仍必须补足准确的隐式 Uses/Defs 或等价描述。[E13]

**仍开放｜验证门禁。**

37B 是本次设计结论；保存编码、别名效果及各合法指令边界恢复仍需 QEMU 实证／需真机实证。失败时不得退回经典 11B 桩。

### 5.3 系统状态限制（v2 修订）

**已裁定（本次设计）**

- 中断开放期间所有受支持 C 路径固定 bank 0、DPS 0；DPS 自动切换等控制也不得启用。
- ISR 及普通辅助闭包不得任意写银行选择、DPS、SPX 等执行环境控制状态。正常算术对标志的修改、编译器生成的合法栈操作及保存／恢复不在此禁令之内。
- 首期受保证的普通中断优先级在启动时确定，开放后不变；ISR 不改变 in-service 环境，不通过伪造 RETI 降低服务层级。
- ISR 可按设备协议修改中断源确认／控制状态，但不得启用描述之外的源、进入 T0 mode3 NMI 或破坏既定抢占关系。
- EA／源使能寄存器不是 37B 上下文中的自动保存对象。首期 ISR 不以手工 EA 管理作为嵌套成立条件，编译器也不自动清／置 EA。
- CPU 入场可能影响定时解锁等非整数状态；此类设备操作不能仅凭“寄存器都保存了”跨越可抢占点。
- 固定 DPS 是仅保存当前 DPX 完整性的必要条件；未来开放切换时必须重新计算状态集合及设备语义。[E19]
- 运行时优先级接管的保证边界见 §9.5，不构成解除本节其他限制的许可。

这些限制同时约束主程序与 ISR、低 ISR 与高 ISR，不只检查 ISR 根函数。

### 5.4 序言／尾声顺序与 DR16 账目（v2 修订）

**已裁定（本次设计）**

序言：

1. 保存 PSW。
2. 使用不需要未保存 scratch 的原生序列保存剩余完整整数上下文。
3. 分配固定局部／spill 帧。
4. 执行 C 函数体。

尾声：

1. 撤销固定局部帧。
2. 按保存布局的正确逆序恢复 DPX 和 DR 集合。
3. 最后恢复 PSW。
4. 紧接 RETI。

“紧接 RETI”表示不插入无关软件指令，**不表示高优先级中断不能在二者之间受理**。该窗口也必须满足完整恢复不变量。

完整保存前不得用 DR16 建锚或破坏普通临时寄存器。所有提前返回经合法尾声；保存／恢复与 FrameSetup/FrameDestroy、栈访存和调度屏障一致建模。

首期不做 shrink-wrapping、保存集删减或序言拆分。中断保存区位于硬件帧与普通固定自身帧之间。

#### DR16 的逐层账目

设主程序 DR16 为 `a0`：

- 低层入场，将 `a0` 保存到低层 37B 区内的 DR16 槽。
- 若低层在某合法执行点的 DR16 为 `aL`，高层入场保存的是 `aL`，位于高层自己的 DR16 槽。
- 高层必须先保存 `aL`，之后才能合法使用 DR16。
- 高层返回恢复 `aL`，使低层原有锚／值继续有效。
- 低层最终返回，再从低层保存区恢复 `a0`。

若高层打断发生在低层保存 DR16 之前或恢复 DR16 之后，同样保存该边界的实际值；不能省略为“低层反正已保存过”。

**首期固定帧仍使用 SPX 相对访问，不因开放嵌套而自动为 ISR 建 DR16 帧锚。**

当前后端仅在可变大小帧时建立锚，而该类帧仍禁止进入 ISR 闭包。[E12] 可以用独立汇编夹具验证“低层稳定 DR16 锚被高层保护”，但不得以夹具通过宣布 C ISR 动态帧已经开放。

未来若为固定 ISR 引入锚，37B 中已保存的 DR16 是否复用、是否还生成普通 `PUSHFP`，必须显式建模：

- 复用只能由明确帧布局规则保证；
- 若另有一次 push，该额外 4B 必须计入自身帧摘要；
- 禁止账面省略或重复计算。

当前 FrameLowering 尾声只接受 ERET，且没有 ISR 保存区，必须进行目标级扩展，不能仅改 AsmPrinter 输出字符串。[E12]

## 6. RETI 建模与完整帧会计

### 6.1 独立 RETI 指令（v2 修订）

**已裁定（本次设计）**

新增独立 RETI 指令及目标返回节点，不将其表示为 ERET 的打印变体。

RETI 至少需要：

- `isReturn`、`isTerminator`、`isBarrier`；
- 正确的硬件帧读取和 SPX 更新语义；
- 首期 PSW1 恢复；
- 当前 in-service 层级结束及先前层级恢复副作用；
- 不可与 ERET 互换的指令身份；
- Source/native 编码核验；
- MC 发射、打印、大小计算及验证全覆盖。

QEMU 将 `0x32` 解码为 RETI，预期为 1 字节，仍需所用编码路径核验。[E18] 目前后端只有 ERET 定义，MC emitter 也仅有 ERET 发射。[E11]

经典 PSW 的软件保存／恢复仍由 ISR 序言／尾声负责。

RETI 不只是“弹另一个长度”：它还结束当前中断服务层级。高层 RETI 只结束高层服务，低层服务仍然有效；它不是“无条件开放全部中断”，也不是“无条件返回主程序”。

普通 ERET 即使偶然获得正确 PC，也不能替代 RETI。

### 6.2 三种入口不能混用

**已裁定（本次设计）**

| 入口契约 | 入场事件 | 退出 |
|---|---|---|
| Near16 普通函数 | ACALL/LCALL，返回帧 2B | RET，弹 2B |
| Far24 普通函数 | ECALL，返回帧 3B | ERET，弹 3B |
| 首期 IRQ 入口 | 硬件中断帧 4B；向量 EJMP 不增栈 | RETI，弹 4B 并结束当前服务层级 |

IRQ 是独立入口种类，不把“四字节帧”伪装成普通 Far32 返回 ABI。[E14]

### 6.3 新 C ISR 的栈会计（v2 修订）

#### 6.3.1 单根固定栈摘要

**已裁定（本次设计）**

首期 ISR 的普通辅助调用闭包统一使用 **Far24／ECALL-ERET**，每条调用边的返回帧为 3B。

闭包中出现 Near16 入口、Near16 调用配置或不能确认的返回帧契约时，本期拒绝。未来支持混合返回帧时，必须改用逐边返回帧大小重新计算，不能静默保留常数 3。

定义：

- `H=4`：本次 IRQ 硬件帧；
- `P_save=37`：本次 ISR 软件保存区；
- `F_j`：ISR j 自身的最终固定机器栈开销，不含 H、P_save 和被调函数开销；
- `A(f)`：普通辅助函数 f 自身的最终固定机器栈开销，不含进入 f 的返回帧和其被调函数开销；
- `Callees(f)`：f 的最终受支持直接普通被调函数集合。

`F_j`、`A(f)` 必须覆盖最终机器代码的局部对象、spill、固定保存、对齐、临时 push 等全部自身固定增栈；不允许仅使用某个早期 IR 或未完整统计的 `StackSize` 代替。

若占用随路径或时点变化，可以使用覆盖所有相关边界的保守上界；不得宣称未证明可同时达到的各项之和就是实测精确峰值。

冻结递归式：

**`K(f) = max({0} ∪ {3 + A(g) + K(g) | g ∈ Callees(f)})`**

对 ISR 根 j，同样按其普通调用边计算：

**`MaxCallStack_j = K(j)`**

从而：

**`W_j = H + P_save + F_j + K(j)`**

`K(j)` 不包含 ISR 根的 F_j、37B 保存区或硬件帧。

调用图无环是递归式成立的首期前提。顺序调用 g、h 取两条同时存活路径中的最大值，不相加；g 尚未返回时调用 h，才沿路径累计。

未知调用、递归环或遗漏的临时增栈使摘要无效。

#### 6.3.2 单层 SPX 账目

设 `S` 为本次 ISR 受理前 SPX，可能属于主程序或下层 ISR。

| 时点 | SPX |
|---|---:|
| 本层受理前 | `S` |
| 硬件入场 | `S+4` |
| 向量 EJMP 后 | `S+4` |
| 完整软件保存后 | `S+41` |
| ISR 固定自身帧完成 | `S+41+F_j` |
| 沿普通调用路径到达峰值 | `S+41+F_j+Σ(3+A(f))` |
| 普通调用全部返回 | `S+41+F_j` |
| 撤销固定自身帧 | `S+41` |
| 恢复软件现场 | `S+4` |
| 本层 RETI 后 | **`S`** |

表中简单帧路径适用于固定开销全部存活的夹具；更一般的机器路径按完整上界摘要验收。

“普通函数调用嵌套”不等于“中断嵌套”，两类同时存活开销都必须计算。

#### 6.3.3 嵌套链公式

令 `J` 包含运行期间可能开放的全部受支持 ISR 根，`p_j` 为其固定优先级。定义允许链：

`Chains = { (j1,…,jm) | p_j1 < p_j2 < … < p_jm }`

未提交可验证排除证明时，保守认为这些严格递增组合均可能发生。

中断总 headroom 为：

**`R = max over Chains [Σ W_j]`**

`J` 为空时取 `R=0`。

本期没有额外经认证的抢占排除关系时，可以等价计算：

**`R = Σ over 已使用优先级 p [max over j∈J 且 p_j=p (W_j)]`**

因此：

- 同级 ISR 不同时在服务，取该级最大值，不能全部相加。
- 不同优先级可能逐级嵌套，必须跨级求和。
- 全部同级时才退化为 `R=max(W_j)`。
- 四个不同档位的无调用、无自身帧 ISR，链需求为 `4×41=164B`；两级为 `82B`，不是 `41B`。

该公式给出保守容量上界。没有执行路径兼容性证明时，不宣称它等于应用真实可达峰值，也不能凭事件通常不同时发生而减小它。

默认不可返回入口如可能受理，按 §9.2 的独立入口开销计入，不能伪装成具有 37B 保存区的 C ISR；同一终止入口被不同槽选择时，按相应源的优先级参与候选关系。

#### 6.3.4 两级精确核算示例

设低层固定自身帧 12B、一个辅助函数自身帧 8B；高层固定自身帧 6B、一个辅助函数自身帧 4B：

- `W_low = 4+37+12+3+8 = 64B`
- `W_high = 4+37+6+3+4 = 54B`

高层在低层最深处受理，峰值为 **`S+118`**。

| 时点 | SPX |
|---|---:|
| 低层普通辅助函数最深处 | `S+64` |
| 高层硬件入场 | `S+68` |
| 高层完成软件保存 | `S+105` |
| 高层固定自身帧完成 | `S+111` |
| 高层辅助函数序言完成 | `S+118` |
| 高层辅助函数 ERET 后 | `S+111` |
| 高层撤销自身帧、恢复软件现场后 | `S+68` |
| 高层 RETI 后，低层辅助函数继续 | **`S+64`** |
| 低层最终 RETI 后 | **`S`** |

这些具体帧大小用于受控夹具。C 端到端测试应根据最终机器摘要核对实际值，不能假设优化后仍具有上述帧大小。

任何保存／栈操作产生更高瞬态 SPX，均必须被上界覆盖；产生覆盖存活对象的瞬态则不是增加 R 可以修复的问题。门禁见 §8.1。

### 6.4 t4 兼容桩与失败形态

**已裁定（本次设计）**

t4 加固桩保存区 11B：PSW/ACC/B 3B，加 R0–R7 8B。正确链最后两次返回分别消费 ERET 的 3B 和 RETI 的 4B。

错误的 `LCALL → LLVM ERET` 链中，LCALL 只增 2B、ERET 减 3B，SPX 相对正确位置少 1B，返回地址混入相邻帧字节，控制流跑飞。不能轻描淡写为“RETI 最后会补平”。t4 的 A/A2/B/C 对照是该禁止规则的依据。[E08]

新原生 ISR 直接由 EJMP 进入，不需要 t4 桩那层 ECALL；也禁止外层桩 ECALL 一个已用 RETI 返回的 ISR。

## 7. 静态参数槽与非重入防线

### 7.1 冲突不只发生于同名函数（v2 修订）

**已裁定（本次设计）**

当前实现中，后续参数经命名 `_PARM_n` 静态槽传递；叶函数槽放 OSEG，可跨函数重叠；非叶放 DSEG。[E09][E10]

必须防止：

1. **同函数重入**：主程序正在准备／使用 `f_PARM_n` 时 ISR 再调 f。
2. **异函数 overlay 冲突**：主程序准备 f 的 OSEG 槽，ISR 调 g，二者物理槽重叠。
3. **低 ISR↔高 ISR 的同函数重入**：低层正在准备／使用 f 的槽，高层再调 f。
4. **低 ISR↔高 ISR 的异函数 overlay 冲突**：低层使用 f 的槽，高层调用具有重叠槽的 g。

保存全部寄存器不保存这些内存。把非叶槽放 DSEG 只解决某些同步调用存活问题，不使其可重入。现有 CALLSEQ 约束防编译器交错，不屏蔽异步中断。[E09]

“不同 ISR”“不同优先级”“各自寄存器都已保存”均不能排除内存槽冲突。

### 7.2 首期防线（v2 修订）

**已裁定（本次设计）**

**每个 ISR 的整个可达普通执行闭包不得分配、读写任何静态参数槽，包括 OSEG 和 DSEG。**

当前普通 ABI 下最直接的允许集合是零参数或一个受支持寄存器参数的辅助函数；安全判断必须最终依据实际 ABI 位置及访问，不永远写死“参数≤1”。

同时禁止：

- 未知外部调用和间接调用；
- 递归及调用图环；
- 未审计 inline asm；
- 可能降成不安全 libcall 的操作，除非最终证明无此调用；
- 通过函数名白名单推断运行库安全；
- 用户“相信我，无静态槽”属性绕过闭包证明。

首期闭包普通调用还必须满足 Far24／ECALL-ERET 契约。

保留 DESIGN D.5 的普通 ABI：不暗改槽宽、不改 overlay 放置、不把普通函数改为栈传参。[E15]

每个 ISR 根独立满足闭包规则，才能在静态参数 ABI 这一维度保护主程序↔ISR 和低 ISR↔高 ISR 的异步重入关系。不能只检查最高优先级 ISR 或单一测试入口。

这里的 ISR↔ISR 是硬件抢占关系，**不是允许 C 函数调用另一个 ISR**。

### 7.3 编译期检查的两条执行责任（v2 修订）

**已裁定（本次设计）**

| 阶段 | A 线：ISR 闭包安全 | B 线：工程可抢占 SPX 安全 |
|---|---|---|
| 前端／契约入口 | ISR 身份、签名、槽号及明显非法调用 | 所有相关 TU 使用一致 ISR-enabled 检查契约；诊断明显不支持的栈操作 |
| IR 检查 | 从全部 ISR 根遍历完整直接闭包，报告失败路径 | 检查普通代码的动态 alloca、stackrestore、其他未认证 SPX 修改，不要求其被 ISR 调用 |
| 优化后检查 | 重查内联／克隆／CC 变化后的闭包 | 重查优化后实际保留的栈操作与安全属性 |
| 最终机器检查 | 静态槽、libcall、未知调用、Far24 契约、动态帧及固定栈摘要 | 覆盖 lowering、晚期展开、inline asm 和辅助调用引入的未认证 SPX 行为 |
| 最终链接 | ISR 注册、安全闭包、调用／入口身份、嵌套栈摘要完整 | 所有最终保留可执行代码具有合格摘要或受控认证资产；跨对象缺信息即拒绝 |

#### 首期保守执行范围

首期 B 线检查 ISR-enabled 工程中**全部最终保留的普通可执行代码**，包括其他 TU、实际链接进来的运行库实现及汇编代码片段。

- 另一 TU 普通函数有 VLA，即使不属于 ISR 闭包，也不能绕过 B 线。
- 仅链接器确实移除、不会进入最终可执行映像的代码可不参加最终门禁。
- 缺摘要对象不能靠符号名白名单、反汇编猜测或用户“相信我”属性放行。
- 未认证 inline asm、不能确定栈效果的控制转移／代码资产不能产生合格摘要。
- 主程序使用间接调用时，不能据此豁免潜在目标代码；最终可执行代码仍须纳入 B 线的保守范围。
- B 线不等于自动证明主程序最大调用深度，M 的责任保持独立。
- 普通代码中的静态参数槽仍依普通 ABI 存在；A 线确保 ISR 不踩这些槽，B 线不改写该 ABI。

启动初始化资产可以有专门认证，例如在中断尚未开放、无 NMI、无遗留服务层级的受控入口建立 SPX。但这种身份必须绑定真实 CRT 资产及入口协议，不能普遍豁免“看起来像初始化”的用户函数。

本期没有全程序“该动态操作一定发生在 EA=0 期间”的证明能力时，采取保守拒绝。局部 SFR 写和注释不能替代跨调用、跨 TU 的不可抢占证明。

诊断应给出类似“ISR → helper A → helper B → 静态参数槽”的完整路径，不以一层或固定深度代替传递分析。

完整闭包检查未落地时，只能提供明确标识的无调用叶 ISR 子集用于 bring-up；它不等于完整首期验收。

### 7.4 运行时纪律仍负责什么（v2 修订）

**已裁定（本次设计）**

无静态参数槽不等于任意共享状态都安全：

- static/global 对象仍可能重入冲突；
- volatile 不提供多字节原子性；
- 主程序与 ISR、低 ISR 与高 ISR 的读改写／缓冲区／外设访问需要应用协议；
- 单字节共享也不能把 `x++` 当不可分割；
- 未认证的 `_Atomic` 不得放行，应检查是否生成 libcall；
- 同一 helper 被低层和高层重入时，其 static/global scratch 同样可能冲突；
- 高层不能自旋等待只有被挂起低层才能释放的锁或完成的事件，否则可能死锁。

首期推荐 ISR 仅确认设备、采样和投递事件，复杂处理移到主循环。

“在 ISR 内关中断”不能修复下层被打断前已写好的参数槽。未来若允许槽路径，临界区必须覆盖槽准备到最后依赖槽的整个生命周期，并处理 overlay 跨函数情况；本期不开放。

优先级和栈安全不提供执行时限或无饥饿保证；高优先级持续触发可能阻止低层推进。

**因嵌套变得更严格的是审计对象、抢占边界及异步冲突组合，不是放宽原来的无静态槽底线。**

## 8. 栈 headroom、任意打断点与嵌套

### 8.1 门禁公式（v2 修订）

**已裁定（本次设计）**

现有链接器仅保证数据区后至少剩余 1024B 栈容量，未证明程序最大栈深度。[E22]

定义：

- `D`：内部 RAM 分配／预留区最高结束地址，exclusive；
- `T = align_up(max(D,0x100),16)+16`；
- `B=T-1`：初始栈顶；
- `E=EDATA_END+1`；
- `C=E-T`；
- `M`：规范化的主程序栈预算，不含中断；
- `R`：按 §6.3 计算的最坏优先级递增链需求。

#### M 的基准

主程序可抢占栈需求定义为：

**`M_preemptible = max over 主程序可抢占边界 t [SPX(t) − B]`**

链接使用的 M 必须不小于该需求；其值是经证明上界，或明确标识的应用预算声明。

“主程序”包括中断可能开放时仍存活的启动／调度包装帧、main 及普通调用链，不仅是 main 自身局部帧。

当前 CRT 设置 SPX 为 B 后通过 ECALL 调用 main，因此 main 执行期间遗留的 **3B CRT→main 返回帧必须计入 M**。[E24]

main 无固定帧、无普通调用且进入 main 后允许中断时，主栈需求不是 0B，而至少为 3B；有其他存活包装帧还须增加。

使用者若提供“main 入口之后额外增长”的预算，构建层必须先加上入口前仍存活开销，再形成规范 M，不能混用口径。

未开放中断的初始化路径也须满足物理栈容量；不能因其不进入 `M_preemptible` 而遗漏普通启动栈需求。其峰值如更大，应提高工程预算或单独检查。

#### 静态门禁

**`C ≥ max(1024, M) + R`**

原有 16B guard 不是顶部 ISR 余量。

所有地址和加法还须满足已认证物理栈范围、SPX 寻址限制及无回绕要求；不能只在主机宽整数中比较后忽略目标栈回绕。当前首期内部 RAM 栈 profile 不因 SPX 的寄存器命名而自动开放更宽栈地址。

#### 运行不变量

设：

`R_>q = max over 全部优先级严格高于 q 的递增链 [Σ W_j]`

在当前服务层级为 q 的可抢占指令边界：

**`SPX_current + R_>q ≤ E-1`**

主程序视为低于所有普通中断的层级，因此 `R_>main=R`。

在 ISR 内，已经存在的下层帧包含于 `SPX_current`，不能把整条 R 重复计入当前层级的剩余需求。

#### 必须执行的门禁条件

1. J 覆盖运行期间可能开放的全部源，不只是启动时已使能的源；可以保守使用全部注册 ISR。
2. 可能使能的未注册槽，其默认终止入口也必须具有已知身份和已计入开销；否则该使能不属于生产契约。
3. 不因应用声明较小嵌套深度而截短实际允许链。配置允许四级递增链而预算只按两层计算时必须拒绝。
4. 不以 ISR 内临时屏蔽某源、外设通常不同步等未经证明的事实减小 R。
5. 未知栈需求不得标成完整上界。主程序无可靠证明时，M 明确标“应用预算声明”；已知需求超过声明即拒绝。
6. **在 ISR 入口才检查剩余空间已经太晚**，嵌套高层同样如此，因为硬件先压入 H。

### 8.2 分字节修改 SPX 的特殊阻塞项（v2 修订）

**已裁定（本次设计）**

当前动态 alloca 和 stackrestore 通过 SPH/SP 两次写回 SPX。[E23] 嵌套使低优先级 ISR 也具有异步受理窗口，但必须分开两条防线。

#### A. ISR 闭包内仍禁止动态帧

每个 ISR 根及全部普通辅助函数继续禁止 VLA、动态 alloca、stackrestore 和未经认证的多步 SPX 写回；最高优先级 ISR 也不例外。

因此首期合法 ISR 不会新增“低 ISR 动态 SPX 更新被高 ISR 打断”的生产路径。

固定帧分配／撤销仍须证明每个可受理边界安全：

- 分配时，先扩展有效栈范围，再使用新空间；
- 撤销时，被释放空间不得仍有后续访问；
- 每次原生 SPX 增减及 push/pop 的指令级效果正确；
- 多条原生增减之间允许抢占，不能把整个固定帧序列假定为不可打断。

#### B. 主程序动态 SPX 更新是独立阻塞项

仅禁止 ISR 动态帧，不能修复主程序自身的分字节 SPX 窗口。

数值反例：

- 扩栈 `0x03F0→0x0410`，高字节先写经过 `0x04F0`，超过最终栈顶 `0xE0`；此时还可能叠加完整嵌套链。
- 恢复 `0x0501→0x04F0`，高字节先写经过 `0x0401`，低于恢复后仍应保护的栈顶；硬件帧可能覆盖存活对象。

第二类问题不能靠扩大 R 修复。

首期生产契约继续禁止可受中断路径上的未认证动态 SPX 更新。未来放行至少需要：

1. 可原子提交 SPX 的机器序列；或
2. 编译器保证顺序、保留原 EA 状态且覆盖全部危险操作的临界序列。

普通 volatile SFR 写配注释不足以认证。由于本期排除 NMI，EA 临界序列才可能成为后续候选；它不在本期自动获准。

#### 主程序侧禁令的执行责任

该约束由 §7.3 的 B 线和 §4.4 的独立对象摘要共同执行，不能只靠 ISR 闭包分析。

必须拒绝如下漏洞：

> ISR 根及 helper 全部通过检查，但另一 TU 的 main/helper 含 VLA；链接器只收集 ISR 摘要，仍把固件标为中断安全。

正确流程为：

1. 检查普通代码实际栈操作；
2. 记录最终机器 SPX 安全摘要；
3. 最终链接检查全部保留代码的摘要完整性；
4. 遇到未认证动态／分字节 SPX 更新或跨对象缺信息时拒绝。

未来开放局部不可抢占动态栈区域，需要单独设计跨调用、控制流及 EA 原值恢复的证明与对象表示，不随优先级便利宏一起自动开放。

#### 稳定锚与动态修改必须分开

主程序拥有稳定 DR16 锚与主程序正在修改动态 SPX 是两个问题。可以用稳定锚夹具验证保存集，不能由该测试推出 C VLA 或动态栈恢复已安全。

**需 QEMU 实证／需真机实证**原生栈操作的指令边界。不要求也不允许在一条原生指令内部人为制造架构不存在的“半条指令抢占”作为生产语义。

### 8.3 优先级配置、受控嵌套与受理时点（v2 修订）

#### 8.3.1 数值契约

**已裁定（本次设计）**

首期标准普通优先级集合为 `{0,1,2,3}`，数字越大越高；每个有效槽必须有显式整数 `priority`。

- 不接受负值、非整数、溢出、缺失值或当前 profile 不支持的档位。
- 不将 4 解释为可配置 NMI。
- 不以 `"high"`、`"low"`、型号名或 QEMU machine 名作为编译器／链接器生产语义来源。
- 两个槽同级合法；不同槽不同优先级也是首期必须支持的正常配置。
- 同级仲裁顺序不用于省略保存或证明共享内存独占。
- 配置在受支持中断开放前完成，受保证运行期间保持不变。

基于四档及严格递增抢占，普通同时在服务深度上界为四；具体工程可能因只使用部分档位而更小。该上界不能与普通 C 调用深度混淆。

#### 8.3.2 初始化责任

**已裁定（本次设计）｜IP/IPH 初始化属于 CRT／启动代码，不属于 ISR lowering。**

启动代码必须：

1. 在全局／源使能仍受控、NMI 路径未启用、无未知遗留 in-service 状态时执行。
2. 按最终数值描述设置固定 bank、DPS 及已认证栈。
3. 按真实寄存器／位映射写入优先级。
4. 按设备协议处理 pending 与源控制。
5. 完成全部初始化及规定时序后，才开放允许的中断。

对映射到 IP/IPH 某位 b 的槽：

- `IP[b] = priority & 1`
- `IPH[b] = (priority >> 1) & 1`

写入必须尊重有效位、保留位及寄存器所有权。不能推广为“所有槽号直接对应同名 SFR 位”。

编译器不在序言自动 `clr EA`，尾声不盲目 `setb EA`，不按函数属性写 IP/IPH。

链接器负责确认初始化资产与所用优先级／栈配置一致，不负责模拟运行时 SFR 写入。

#### 8.3.3 任意合法指令边界支持高打断低

**已裁定（本次设计）**

安全证明必须覆盖低层：

- 向量 EJMP 前后、第一条保存指令之前；
- PSW 保存后；
- 整数保存中途；
- 固定帧分配中途；
- C 函数体、WR/DR 值存活、比较／分支和进位链之间；
- 普通辅助函数、参数寄存器准备、ECALL/ERET 前后；
- 固定帧撤销中途；
- 寄存器恢复中途；
- PSW 已恢复、RETI 尚未执行的窗口。

不能假定“进入 C 函数体后才允许嵌套”。只要硬件可能更早受理，高层就必须恢复更早边界的真实状态。

同级屏蔽由 in-service 机制覆盖整个服务期间。高层 RETI 恢复低层服务级别后：

- 与低层同级及更低级的请求仍被阻止；
- 高于低层的请求重新具备受理资格；
- 不保证高层返回后一定先执行完低层 ISR；
- 最外层 RETI 才恢复无 ISR 状态。

#### 8.3.4 模型证明项与硬件证明项

**已裁定（本次设计）**

| 要验证的性质 | 当前 QEMU 可承担的工作 | 硬件边界 |
|---|---|---|
| 数值档位、严格高于当前层级才受理 | 在已接通源上执行功能探针 | 仍需逐板真机子集 |
| 高层 RETI 恢复低层服务状态 | 检查层级、返回 PC、SPX 和 pending 的逻辑关系 | 不推导下一条硬件指令的具体时点 |
| 保存／恢复中途上下文完整性 | 在明确模型指令边界注入请求，验证全部现场 | 真机是否由该外设安排命中相同边界，另行证明 |
| 两级／多级峰值栈 | 模型内精确核账及哨兵 | 真机验证对应入口帧和最大支持链 |
| EA=0 对普通可屏蔽源的功能屏蔽 | 可测试逻辑行为 | EA 修改后受理延迟不能由当前模型认证 |
| RETI／IE／IP／IPH 后的一指令延迟 | **当前模型不支持** | **待真机验证** |
| 外设触发至受理的周期／流水线窗口 | **当前模型不提供周期精确证明** | **待真机验证** |
| IP2/IP2H、IP3/IP3H 对应扩展源 | 当前 STC32G 基线不具备相应模型能力 | 冻结板级映射后另行验证 |

“精确命中保存中途”的模型测试，可以证明保存序列在该模型边界恢复正确，不得命名为“硬件精确受理时序已通过”。

测试记录至少区分：

- **PASS／FAIL**：仅针对所选基线支持且实际执行的断言；
- **未执行**：模型支持但尚无结果；
- **不支持／待真机**：模型明确缺项；
- **基线不匹配**：二进制不符合冻结身份。

实证清单包括：

1. 四档编码、比较方向及同级不可抢占。
2. 低层已执行后才产生高请求，确实形成高打断低。
3. 保存前、保存中、恢复中及 RETI 前窗口。
4. 高层 RETI 后低层服务状态恢复，低层同级 pending 不得过早进入。
5. 高层返回后，中间优先级请求按恢复后的层级规则进入。
6. 多层 RETI 后深度逐层减少，无服务层级泄漏。
7. T0 mode3 NMI 被工程配置排除，普通优先级测试未意外经过该特殊路径。
8. 硬件受理延迟与精确触发时序另行真机登记。

时序差异必须显式记录，不能为让测试通过而重新要求全部同级。

## 9. 向量表与板级配置

### 9.1 槽号含义

**已裁定（本次设计）**

ABI 定义 N 为向量描述槽序号；板级提供槽地址、可注册性和硬件帧 profile。

首期八槽：

`address(N)=0xFF0003+8N`

对应 INT0/TF0/INT1/TF1/UART1/ADC/LVD/PCA。该公式不是所有 MCS251 派生芯片的永久语义。

外设名称及确认方法属于板／设备层；前后端不按槽号自动发清标志代码。八槽表的可生成性不等于八路外设触发或优先级验证完成。

### 9.2 链接器生成唯一向量表与默认终止入口（v2 修订）

**已裁定（本次设计）**

历史机制事实：当前 CRT 是完整八槽默认网、无弱符号、整表替换惯例。[E24]

新生产方案采用**链接器拥有唯一向量表**：

1. 各 ISR 对象只提交注册记录，不各自生成绝对表。
2. 链接器按数值板级描述构造完整表。
3. 已注册槽 EJMP 至 ISR。
4. 未注册槽 EJMP 至经认证的默认 IRQ 终止入口。
5. 每槽 8B：4B EJMP＋4B 填充。
6. 重复注册、非法槽、非 ISR 注册目标、未定义目标、向量区重叠均报错。
7. ISR 目标作 GC 根。
8. 旧 CRT VECS 与新表不能共存。

默认处理器继续 fail-stop，不采用未用槽直接 RETI 的行为，防止静默中断风暴。CRT 必须提供配套新启动资产，不是在构建中临时删几行旧汇编。

#### 默认 fail-stop 的身份与安全范围

默认入口是独立认证的不可返回 IRQ 终止入口，由链接器专门选择，不参与普通 ISR 注册豁免。

推荐首期终止资产：

- 不调用普通 C 函数；
- 不使用额外软件栈；
- 不执行 RET／ERET／RETI，不返回被打断代码；
- 尽早屏蔽普通可屏蔽中断，然后保持终止状态；
- 不在屏蔽前进行可能触发其他中断的日志或外设事务；
- 不依靠 EA 屏蔽 NMI，本期仍排除 NMI。

即使第一条软件指令将屏蔽中断，高优先级请求仍可能在它执行之前抢占。因此不能把默认入口入场视为“零栈且立即全局不可抢占”。

若上述零软件增栈资产通过认证，其单次入口开销为 `H=4B`，无需为永不恢复的下层建立 37B 软件现场；在屏蔽生效前仍可能存在更高层，须保守计入相应链。

任何新增日志、push 或调用都会改变开销及闭包，必须重认证。缺少默认入口身份或开销信息时拒绝生产链接。

符号名 `__mcs251_isr_unhandled` 可以作为资产关联名称，但**不能仅靠名称授予身份**。用户普通函数改成该名字或添加 `noreturn` 不能获得 IRQ 入口资格。

### 9.3 复位三字节陷阱

**已裁定（本次设计）**

复位区域严格保留 `[0xFF0000,0xFF0003)`：

- 复位桩最多 3B；
- bank 内 LJMP 到 BOOT 或跳板；
- 不允许 reset 槽放 4B EJMP；
- 不允许把 SPX 初始化放进该区域；
- 链接器检查实际范围与跳转可达性。

旧探针文档“LJMP 两字节”的文字不一致，以当前 CRT 三字节 LJMP 和最终编码检查为准。[E24][E25]

### 9.4 数值板级描述与启动配置（v2 修订）

**已裁定（本次设计）**

原十二变量：

FLASH_BASE/EDATA_END/CSEG_BASE/XINIT_BASE/EEPROM_MAX/HRIC/BAUD/UART_RELOAD/LED_PORT/LED_BIT/QEMU_MACHINE/QEMU_NOTE。[E26]

它们的含义保持不变，但不足以描述向量、优先级、使能映射及嵌套预算。

ISR-enabled 构建增加规范化数值输入，至少包含：

| 类别 | 必需内容 |
|---|---|
| 向量拓扑 | 槽号、地址／间距或显式地址列表、有效／保留／可注册性 |
| 入口 | 硬件帧 profile |
| 优先级能力 | 有效档位集合或等价数值范围；首期基线 0–3 |
| **每槽优先级** | **显式 `priority` 整数** |
| 寄存器映射 | 优先级低／高位对应寄存器地址、位位置、有效／保留位规则及启动协议 |
| 源使能 | 与优先级映射分离的使能信息、运行期间允许开放的源集合 |
| 嵌套约束 | 固定优先级推导的抢占关系；如另设部署深度上限，须验证而非截断链 |
| 安全协议 | ISR 闭包与普通可抢占 SPX 检查契约及对象摘要版本 |
| 栈 | 主程序预算 M、逐根最终机器上界摘要、推导 R |
| 一致性 | 数值描述版本、CRT／初始化资产版本及配置指纹 |

有效槽包括未注册槽，也必须有确定优先级，不能缺值后静默补成“全部 0”。保留槽不得因填写优先级而变得可注册。

板能力给出“能配置什么、如何编码”；应用选择给出“各槽本次配置多少”。构建层合成最终描述后，CRT 与链接器消费同一结果。

例如槽 1 配 0、槽 3 配 2、槽 4 配 3，不要求 C 定义增加第二参数。

若多个描述项共享同一硬件优先级控制位而请求矛盾，必须拒绝，不通过写入先后顺序决定最终含义。

链接阶段必须：

- 校验每个优先级及映射合法；
- 确认注册／可能使能源具有已认证入口与栈摘要；
- 建立严格递增抢占关系，推导最大服务深度和 R；
- 拒绝小于实际允许深度的声明上限；
- 校验启动配置一致；
- 优先级变化重新计算 headroom，并使相关配置产物失效或重建；
- 将有效数值描述、启动资产、检查协议和预算纳入配置指纹。

缺描述时拒绝 ISR-enabled 链接，不按 BOARD 或 QEMU machine 猜默认。编译器／链接器不读取板 Makefile、不按器件名分派，继续遵守 E.5。[E16]

槽号大于 7 的扩展仍需逐板冻结实际中断源、保留槽、地址、优先级／使能映射和布局；不得仅调大 count。增长后还须检查与 BOOT `0xFF0100`／CSEG 重叠。

扩展 IP2/IP2H、IP3/IP3H 的描述能力，不构成当前 QEMU 支持承诺。板上具有某源、模型具有某个 IRQ 数组元素、该源实测通过，是三件不同的事。

### 9.5 三层优先级配置与责任边界（v2 修订）

#### 第一层：初始配置——首期受保证范围

**已裁定（本次设计）**

每槽初始优先级来自唯一规范化数值描述，与 ISR 注册、CRT 初始化、编译检查契约、最终抢占图和 R 绑定。

CRT／启动代码在受控未开放阶段完成 IP/IPH 写入。编译器不在 ISR 序言设置优先级，不在尾声恢复 IP/IPH。

首期保证的前提包括：

- 初始化完成后优先级不变；
- 可能使能源集合不越界；
- NMI 排除条件保持；
- 其他入口、保存、静态槽及 SPX 契约成立。

#### 第二层：运行时操作工具——后续可选便利设施

**仍开放；不进入首期硬范围。**

后续可以提供形如 `*_SetIntPriority(n)` 的便利宏或接口。STC 官方宏存在，只说明这种操作习惯常见，不自动证明更新过程无重入或原子安全。

本次亲读的官方宏分两步写优先级低位和高位，没有在宏内建立完整临界区；某些宏多次使用实参。[E32]

后续设计本项目接口，应独立规定：

- n 的合法整数范围、动态值检查及求值次数；
- 寄存器／位映射和保留位规则；
- 两次写入间的抢占防护与编译器顺序保证；
- EA 原值保存／恢复；
- pending 请求及重新开放时序；
- 与正在服务 ISR 层级的关系。

不能把两次 volatile 写宣称为一次原子优先级修改。便利头只向后端提供数值映射；生产语义不能按宏名、型号名或函数名分派。

首个可认证运行时重配置方案，推荐限定为**主程序上下文、没有在服务 ISR、普通中断已受控屏蔽、NMI 排除**的静止重配置阶段。

低 ISR 中执行 `clr EA` 并不消除已有 in-service 层级，也不自动满足该条件。

不要求与 STC 宏同名同形，不承诺 `stc.h` 或官方 demo 原样可用。

#### 第三层：用户接管——保证范围必须显式变化

**已裁定（本次设计）**

用户运行期间改变优先级后：

1. 初始槽描述计算的抢占图不再代表当前配置。
2. 初始 R 即使数值偶然仍足够，也不能继续作为已证明上界引用。
3. 新配置、过渡阶段、可能嵌套链、物理栈容量及共享状态重入由用户另行证明。
4. 在已有 ISR 服务期间改变档位，不能仅按新档位排序推断全部已挂起层级；不能简单沿用固定配置下的四层证明。
5. ISR CC、完整保存、禁止普通调用 ISR、无静态槽闭包和 SPX 安全规则仍然有效，不能被“用户接管优先级”一并关闭。

首期不提供通用“忽略安全检查”开关放行此行为。

受保证配置中发现非初始化优先级写入，应诊断其违反固定配置契约；不能仅发可忽略警告却继续标记“固定优先级安全验收通过”。

未来用户接管模式必须具有明确配置／产物状态和责任声明。诊断开关可以补充提醒，但关闭警告不恢复静态证明。

编译器不声称能识别任意指针或手写汇编伪装的 SFR 写入；未知副作用须按各项检查的保守规则处理。

## 10. 验证计划

### 10.1 lit 与静态链测试（v2 修订）

**已裁定（本次设计）**

| 层次 | 必需覆盖 |
|---|---|
| Sema 路由 | mcs251 不再产生 ARMInterruptAttr；合法槽号产生专属属性 |
| Sema 负例 | 无参数／多参数，包括 `interrupt(N,P)`；负槽号、非 ICE、溢出、签名错误、重声明冲突、重复槽 |
| 使用限制 | 普通调用 ISR、ISR 调 ISR、取地址、转换逃逸、naked、always_inline、错误 CC |
| IR | CC＋槽号保留；声明／定义一致；文本／bitcode round-trip |
| 优化 | O0/O2、GlobalDCE、IPO、克隆／内联不丢注册、不降普通 CC |
| Backend | 普通函数 ERET、ISR RETI；早返回；固定帧／spill；每层 37B 布局、逆序恢复、隐式别名 |
| 内部调用 | 辅助函数仍 ECALL/ERET；无尾跳绕过恢复 |
| 闭包负例 | 深层静态槽、未知 external、函数指针、递归、libcall、未审计 asm、动态帧；每个 ISR 根均检查 |
| MC | RETI 编码／大小；所用 push/pop 编码；汇编与对象路径一致 |
| 向量链接 | 八槽映射、默认兜底、重复注册、非法槽、错误入口、GC、旧 VECS 冲突、ROM 冲突 |
| 优先级正例 | 0、1、2、3；同级多槽合法；不同优先级合法；调整优先级改变抢占图、R 和指纹 |
| 优先级负例 | 负值、4 及更大非法值、溢出、非整数、缺失 priority、能力不匹配、映射冲突、CRT 配置不一致 |
| 深度门禁 | 声明深度低于实际递增链时报错；不得按声明截断链 |
| 栈门禁 | 同级取最大、跨级求和、混合配置逐级最大求和；两级／四级；恰好边界和差 1B 失败；未知摘要拒绝 |
| 跨 TU 主程序 SPX | ISR 闭包安全，但另一 TU 普通函数含 VLA／stackrestore／分字节 SPX 时拒绝 |
| 缺摘要对象 | 旧对象、实际链接库实现、汇编缺 SPX 摘要时拒绝；不得靠符号名放行 |
| 检查线独立 | 普通静态参数槽不因 B 线被全面禁止；ISR 闭包同类槽仍由 A 线拒绝 |
| 优化后摘要 | 优化／LTO／晚期展开后摘要与实际栈操作一致 |
| M 基准 | CRT→main 3B 已计入；入口前后两种预算口径不得混用 |
| K 递归式 | 顺序兄弟调用取最大，嵌套路径求和，多分支取上界，调用环拒绝 |
| 返回帧配置 | ISR helper 出现 Near16 或未知返回帧时拒绝，不静默使用 3B |
| 默认入口 | 普通函数、仅 `noreturn` 函数、伪造保留名、用户注册默认入口均不能绕过身份 |
| 配置写入责任 | 区分 CRT 合法初始写入与未认证运行时写入；关闭警告不能保留错误认证状态 |
| 模型能力门禁 | 请求当前模型不支持的 deferral／扩展源验证时明确“不支持”，不生成 PASS |
| 红线 | 同一数值输入不因板名不同改变生产语义 |

优先级非法值测试针对板级解析／配置／链接入口，不改变单参数 C 属性语义。

至少保留一条 C→IR→对象→链接完整链，并新增“相同 C ISR、不同合法优先级配置、不同 headroom 结果”的端到端测试。

#### 10.2.1 历史 t4 与新 ISR qualification 分别冻结

#### 10.2.2 适用性检查先于运行判定

- IRQ 0–4 的普通优先级、嵌套、层级恢复和模型指令边界保存测试可以执行。
- 八槽表的链接布局可做静态测试，但不因此宣称八路外设触发通过。
- 扩展 IP2/IP2H、IP3/IP3H 及额外 UART／Timer 的当前模型验证记“不支持”。
- one-instruction deferral 和周期精确受理时序记“不支持／待真机”。

通用宿主 IRQ 注入只能证明相应控制器逻辑，不能冒充外设接线测试。

#### 10.2.3 必需探针

按序执行并留存源码、工具身份、模型身份、镜像摘要、配置描述、完整日志和精确断言：

1. **历史返回帧对照。**保留 t4 四组：LCALL/ERET 错配预期失败；LCALL/RET、ECALL/ERET、加固桩正控制。禁止以经典 11B 桩替代本设计保存验证。
2. **四字节硬件帧。**核对入口／返回 SPX、帧字节、PC、PSW1；确认所用 profile；测量寄存器不能与寻址寄存器别名自伤。
3. **单层完整保存。**独立 DR／DPX／PSW 哨兵，WR/DR 运算、高寄存器压力和 spill；不得只检查 R0。
4. **四档配置。**通过实际 IP/IPH 写入验证 0–3；检验高选低、同级仲裁模型行为和同级不抢占。
5. **同级 pending。**在某层服务期间产生同级请求，确认不会在该层 RETI 前进入。
6. **低层执行中途触发高层。**先确认低层已到指定点，再产生高请求；记录低进、高进、高出、低续行。不得以二者预先 pending、高层先执行冒充嵌套。
7. **入口／尾声窗口。**向量、首条保存前后、保存中、固定帧操作中、恢复中、PSW 恢复后 RETI 前分别制造请求，核对完整状态和返回 PC。
8. **DR16 分层。**主程序稳定锚、低层稳定 DR16 值／锚、高层修改 DR16，逐层确认高退低、低退主的值；低层锚夹具独立登记，不开放动态 ISR。
9. **RETI 层级恢复。**至少覆盖“主→低→高→低→主”；高层返回后低层同级请求仍被挡住，同时允许高于低层的中间档请求按规则进入。
10. **两级栈精确会计。**低层到普通调用最深处后触发高层；逐点记录 §6.3 的 SPX 变化、保存区哨兵及最终无漂移。观测峰值与最终机器摘要一致。
11. **四档递增链。**为完整四档产品能力验证 0→1→2→3 的服务深度、逐层返回和栈峰值。两级通过不等于四层验证完成。
12. **任意普通指令边界。**比较／分支、进位链、参数准备、ECALL/ERET、普通序言／尾声、spill 访问；主程序与低 ISR 两类受害上下文均覆盖。
13. **静态槽负例夹具。**主程序↔ISR、低 ISR↔高 ISR 的同函数和异函数 overlay 冲突；演示错误后验证生产工具拒绝。夹具不经安全开关进入生产路径。
14. **SPX 瞬态负例。**复现两类分字节窗口，使用合法 RAM 哨兵；增加嵌套对瞬态 headroom 的压力。不得靠大板没崩掩盖越界，也不得转写为动态帧支持。
15. **受理延迟模型记录。**留存当前 RETI／IE／IP／IPH 后受理行为，确认其与已声明模型限制一致；不作为硬件延迟 PASS。硬件时序断言交真机验证。
16. **长期重复与默认网。**反复嵌套／返回、主循环推进、SPX 无漂移、服务层级无泄漏、默认槽 fail-stop。

关键点必须用可控 pending、单步或明确触发窗口证明确实命中；定时器压力只能补充覆盖。

运行纪律：

- 无 icount；
- 轮询＋超时；
- timeout 不是通过；
- UART1 IRQ 开放时日志可能自触 TI，优先记录 RAM 后关中断统一输出；
- 外设计数精确断言由 ISR 停源或明确设计多次触发；
- 源码与冻结二进制身份不一致时分开记账；
- 时序标记及测量寄存器不得破坏被测现场。[E08][E17][E25]

### 10.3 真机子集（v2 修订）

**已裁定（本次设计）**

严格先完成可由 QEMU 承担的功能验证，再提交对应真机项；模型明确不支持的时序项不要求伪造 QEMU PASS，而应在能力矩阵中挂起至真机。

首轮真机包含：

- 定时器单发和重复 ISR；
- SPX、完整整数现场及稳定 DR16 锚保持；
- ISR 内普通 ECALL/ERET 辅助调用；
- 同级 pending 被阻止，并在服务结束后的合法时点受理；
- 受控两级高打断低：先执行中途，再保存／恢复窗口；
- 高层 RETI 恢复低层服务状态及原 SPX；
- 两级峰值栈和上下保存区哨兵；
- 板支持条件下的 INT0／UART1 确认纪律；
- 专门登记 RETI／使能及优先级寄存器写入后的硬件受理延迟。

完整四档／四层产品验收还需覆盖相应最大链及压力测试；仅完成首轮两级子集时明确标示覆盖范围。

不在首轮执行：

- 故意返回帧错配；
- 故意栈越界／硬件帧破坏；
- NMI／T0 mode3；
- 未认证高槽来源；
- Flash 擦写及危险配置写入；
- `0xFF RSTCFG`。

IP/IPH 的受控启动初始化属于必要配置，不属于笼统禁止的“所有 SFR 配置写入”。

G12、G144 真机分别登记。QEMU 上运行某板固件不能替代该板硬件的优先级、受理时序和栈语义证明。

## 11. 实施依赖与验收口径（v2 修订）

**已裁定（本次设计）**

依赖顺序：

5. QEMU 单因子确认硬件帧、完整保存、RETI 服务层级及高打断低窗口。
6. 接通 AST→IR→MachineFunction→完整保存／固定帧→RETI。
7. 完成全部 ISR 根的 A 线闭包检查，以及普通保留代码的 B 线 SPX 检查。
8. 接通 ELF 向量注册、唯一完整表、GC、优先级抢占图和链式 headroom 门禁。
9. 完成 C 端到端、两级／最大支持链回归。
10. 提交真机子集和模型不支持的硬件时序项，冻结差异说明。

必须分别报告：

- 设计已裁定；
- 编码线格式已冻结；
- 工具已实现；
- 静态测试已通过；
- QEMU 已验证；
- 当前模型不支持；
- 真机已验证。

“属性能编译”“IR 中能看到字段”“汇编出现 RETI”“t4 能返回”“单层能返回”“同级测试通过”“两级没有崩”均不是完整 C ISR 支持的单独退出条件。

完整退出条件还包括：

- ISR 闭包安全与普通可抢占 SPX 安全两条检查线均闭合；
- M／F／A／K 数学口径与最终机器摘要一致；
- 默认入口身份和开销已冻结；
- 两个验收基线分别可识别；
- 模型不支持的断言明确挂起至真机，而非虚构 PASS；
- 首期产物满足固定优先级契约，没有因运行时用户修改而继续引用失效的 R 证明。

**不同优先级配置及受控嵌套是首期验收项，不是后续可选优化。**

验证未完成时标记未完成，不能静默退回“生产只允许全部同级”。

APPROVE-WITH-NOTES 表示设计骨架可继续推进，不表示实施前注记 N1–N3 已经实现或通过验证。

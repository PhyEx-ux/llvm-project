## 1. 问题、语义边界与首轮范围

### 1.1 预算问题与现行存储机制

- demo 41 完整 CSEG 需求历史实测 76084B；S3 裁剪后为 70763B（探针提供者）/
  70858B（S2 产品闭包），对 63744B 窗口仍差 7019B/7114B。S4 比较采用后者，
  不重复扣 S3 收益；完整 printf 形态 +S4 未单独测量，不作预算承诺。
- AS4（`code`/`__code`）对象是 CSEG 只读镜像。AS3（`__xdata`）对象为每符号
  一个 `.mcs251.XSEG.<sym>` NOBITS 节及一条 `.mcs251.xdata_init` 记录；
  非零初始化时为 7B 头 + 完整 payload。迁移把 CSEG 表字节移到 XDATA RAM，
  ROM 初值映像改占 FE 的 XDATA_INIT 槽，并非删除初值。
- HEAD `/home/liu/LLVM_STC32/MCS251/llvm/lib/Target/MCS251/MCS251AsmPrinter.cpp`
  **2232–2313** 明确覆盖 `const __xdata`；2291–2293 仍发
  `SHT_NOBITS`、`SHF_ALLOC | SHF_WRITE`；2304–2313 保留初始化记录。
  **const 只恢复源级正常写入纪律，不恢复 CODE 存储保护**。去 const 别名、
  错误指针或其他写入路径仍可能破坏 RAM；本路径的拒绝门不等于硬件写保护。
- 表仅在 **CRT 完成初始化后可读**；早期启动和提前中断消费者不在可迁移域。
  对象数据地址变化是本变换的**允许差异**；地址数值比较、固定地址依赖、
  指针整数化等地址可观察行为不在保等价承诺内，发现即拒绝该 S4 构建。

### 3.3 const AS3 消费闭包（全集冻结）

闭包由六个对象及所有引用它们的对象/函数类型通道起算，全 TU 枚举；不能将

1. **对象类型**：六定义及所有 extern/重声明均为 const AS3；元素及聚合内容
   不变。直接下标/字段读允许，对象范围内索引与消费方局部参数指针递增读允许；
   写入、越界读取不在许可域。
2. **函数通道**：覆盖消费函数定义、所有声明、所有调用点、typedef 别名和
   函数指针类型；任何经过的 pointee 都保持 const AS3。当前允许的跨 TU 表指针
   边仅为 `USER/test.c` 四处 `Gui_Drawbmp16(..., gImage_qq)` 调用，经

   gui 五表仅按其已绑定源码直接读取；不授权新消费者或新调用边。
3. **类型拒绝全集**：AS3→泛型/AS0/AS4、去 const、任何指针整数化（含再转回）、
   未知外部消费者、不可分析间接调用一律拒绝；不得显式或隐式 cast 绕过。
   typedef/函数指针通道必须纳入扫描而非漏检；本轮不新增函数指针消费边，

4. **逃逸拒绝**：除上述直接调用传参和消费函数内部的局部游标读取外，指向
   迁移对象的指针被保存（全局/静态/聚合/其他存储）、返回或继续传递，均为

5. **地址/时序**：禁止依赖原 AS4 数值地址、固定地址或指针表示；允许数据地址

   不能证明该前提也拒绝，不靠普通 main 路径测试掩盖早期消费者。
6. **跨 TU 身份**：所有相关 TU（本轮为全部五 TU）从同一影子输入全量重编，
   以 P3/P5 构建身份检查拒旧对象；语义类型核验须保留源类型证据，不能只靠
   LLVM opaque pointer、指针同宽或最终链接接受。

## 4. 预算、型号与相邻能力边界

### 4.1 三类上限独立成门

下列三门互不替代、均强制，先用宽整数做算术再检查，禁止 u16 截断后比较。

| 门 | 强制合同 | 本例历史复核 |
|---|---|---|
| L1 单对象记录字段 | 每对象 **1..65535B**；普通 copy 记录 `object_size=payload_size=完整对象尺寸`，目的区在单个 64K 窗内 | 六对象各自通过，最大 3200B；不是以 8972B 合计代替单对象检查 |
| L2 初始化流 walker | **分别**检查 `0 ≤ l_XDATA_INIT ≤65535`、`0 ≤ l_XINIT ≤65535`；必须完整解码每流到末尾，不能以二者合计代证 | 9014B 与 104B 分别通过；9118B 只作 ROM 记账 |
| L3 地址布局/板级容量 | 两个 FE 槽独立检查；所有 CODE/初始化区间统一重叠、24 位边界及 ROM gate；所有 XDATA 实际占用区间连同跳窗洞、板级保留/占用核验 | 见下表；仅本布局成立，不等于容量门已经执行 |

S4 G144K246 profile 必须显式固定 `--area-start=XSEG=0x010000`，并强制
**`--xdata-size=0x20000`**；不改 lld 选项自身可选语义。HEAD
`/home/liu/LLVM_STC32/MCS251/lld/MCS251/LinkerCore.cpp` **3058–3075** 的
`if (Config.XdataSize)` 表明仅提供非零选项才执行该容量门；它逐节检查
`Lo ≥ Base && Hi ≤ Base+N`。缺该选项在 S4 harness 的配方预检即拒，不能等
链接器自己失败；正式验收还要有真实超限负例。相对容量门不能代替板级绝对窗口。

| 区域 | 固定区间/上限 | 验收要求 |
|---|---|---|
| XINIT 前槽 | **[0xFE0000, 0xFE0280)**，640B | 历史 `l_XINIT=104 ≤640`；实现重测本例值且单独过 L2 |

### 4.2 G13b 非依赖与未来超限拒绝路径

- 本例仅六条普通非零 copy 记录，**不依赖 G13b 切分**；依赖表 §6.1 明列。
- 将来即使扩展名单，**非零初始化对象 ≥65536B 在本 S4 路径仍拒绝**：
  不截断、不手工切数组、不设置 SPLIT 标志绕过；须另开设计，不能当成政策配置。
- G13b r4 **§3.1.1 仅放行全零大对象的 clear-only 切分**，非零大对象仍拒。
  不能借其能力承诺 S4 非零 payload 切分，也不把本轮名单改为全零大对象路线。
- 即使单对象为 **65535B**，非零单记录总长也是 **65535+7=65542B**，
  已超过 **65535B walker 界**，也超过 **64896B FE 后槽**。L1 合法不蕴含
  L2/L3 合法；当前 allowlist 先拒名单外对象，独立边界测试仍须覆盖这条推导。
- 本轮六迁移对象不带 FIXED/SPLIT、无 placement 约束。与其他已批准能力同链
  时遵守 G11 修订 7 §4.1 的**“可同链、不可同节”**：合法 FIXED 实体与动态
  XSEG_SPLIT 可在不同节共链，同一 fixed 节携带 SPLIT 必拒，普通 S4 节不混入两者。
  共用统一重叠、容量及 CODE 镜像预留检查，不绕过 XDataUsed/CodeUsed；若集成
  基线包含 G11/G13b，按双方已集成能力做组合回归，不把未实现能力列为 S4 依赖。

## 1. 需求精确化

### 1.1 demo 85 的 XDATA 对象集（BV-1 后）

BV-1（AGG §B.5.1 已裁）的 demo 侧形态 = XDATA 半按板级容量排布 + **移除 `eRAM`
数组及相关测试**。移除后 XDATA 对象集为：

| 对象 | IR | 尺寸 | 说明 |
|---|---|---:|---|
| `xRAM1` | `addrspace(3) global [65536 x i8] zeroinitializer` | 65536 | **恰超 u16 限 1 字节，本缺口主体** |
| `xRAM2` | 同上 | 65536 | 同上 |
| `xRAM3` | `addrspace(3) global [4096 x i8] zeroinitializer` | 4096 | 现行已通过 |

合计 **135168 B = `0x21000`**，与板级可用跨度（128K XDATA `[0x010000,0x030000)` +
4K EXEC RAM `[0x030000,0x031000)`，AGG §B.3.5）**精确相等，零余量**——任何额外
XSEG 字节（含 bank-jump 洞）都会越板。这一事实直接约束设计：**形态 (b) 的实现
不得引入任何地址空间浪费**（这也是"源级拆 4×32K"之外一切带 padding 的拆法被否的原因，
见 §3.2）。**容量断言状态：未证实**——须待 D5 裁定并同步 §7.3/§7.4 冻结文本之后，
以正式链接测试（§5 G-T4/G-T11）确认；探针 rc=0（§2.7.3）不是产品实现证明（评审 7）。

> 与 eRAM 半的分离（评分要求 3）：AGG r2 的 **B-P2d**（`eRAM` 缩小到 ≤15088 B 进
> EDATA，边界值恰得 1024 B 栈容量）是 PM 已裁的 demo 侧可行解的 **eRAM 半**，
> 属 **DF4 依赖路径**（AS8 通路未实现 + 栈门禁，AGG §B.4.2/§B.4.3）；BV-1 采用的
> 则是更早一步的"移除数组"。**两者都属 eRAM 半，与本文的 XDATA 半（G13b）互不依赖、
> 可独立推进**；G13b 落地不改变 16074 B 违反 G144 栈门禁的结论。

### 1.2 连续性假设核对（源码证据）

当前语料 `mcs251-demos-rewritten/src/85-内部148K字节SRAM读写测试/sample.c`：

- `:95` `long index;` —— 循环索引为 **32 位**，`:119` `for(index=0;index<XDATA1_LEN;index++)`
  覆盖 xRAM1 全部 65536 元素（若索引是 u16 会在 65536 处回绕，语义自毁）；
- `:119-154` 全部访问形如 `xRAM1[index] = ...` / `... != xRAM1[index]`，即
  **基址符号 + 索引**，无 `p + 65536` 式跨对象指针算术、无对象间别名假设；
- 无 `_at_` 残留依赖（改写已丢弃；顺序放置恰复原地址是巧合，AGG §B.3.3 R3）。

结论：

1. **对象间**不需要物理连续（三个对象相互独立，顺序放置即可）；
2. **对象内**必须连续：`xRAM1` 是一个 65536 元素数组，数组下标语义 + IR GEP 线性
   语义要求 `[base, base+65536)` 地址连续。运行期跨 bank 线性寻址**已被现有后端
   支持并被冻结测试钉死**：`llvm/test/CodeGen/MCS251/xdata-runtime-banks.ll`
   （X2-1：`p + 65536` 的 32 位加法进位入 bank 字节，每次 movx 前按位 [23:16]
   重装 DPXL；`ld_index` 用例即寄存器索引跨窗形态）。

因此 G13b 的正确目标是**保留语言层单对象完整性**（单节、单区间、连续），让
"恰 65536 B（乃至任意 ≤24 位空间）的全零 `__xdata` 对象"端到端可用——而不是
像 BV-1 那样在源级拆掉数组、放弃连续性。G13b 落地后，demo 85 的 `xRAM1`/`xRAM2`
可以**不再拆分**（BV-1 的拆分改写被能力替代；容量零余量与 eRAM 移除仍不变）。

### 2.2 为什么"llc 发多条记录"不可行（适用范围：当前 v1 记录格式 + 无链接期重写机制）

形态 (b) 若理解为"llc 把一个大对象拆成多条 v1 记录发射"，在**当前 v1 记录格式
及无链接期重写机制**的前提下存在一个数学障碍（评审 8：本反证只对该前提负责，
不排除可重定位分段描述等其他设计——如形态 (a) 的 v2 记录或未来新增的重定位通道）：
记录的 `bank`/`window` 字段虽经重定位解析（`emitXDATAInitAddress`，HI8/MID8/LO8
三字节通道，`MCS251AsmPrinter.cpp:813-817`），但**切分的偏移必须在最终放置下落在
窗口边界或窗内**。llc 不知道放置地址：

- 若按固定偏移（如 0x8000）拆：符号落 `0x10800` 时第二条记录覆盖
  `[0x18800, 0x20800)`——跨窗，被 `validateXDATAInit:3864` 硬拒；
- 若按 65535 拆：同样依赖起点相位。

⇒ **在上述前提下，切分算法只能由掌握最终地址的一方（lld）执行**。这是形态 (b)
工程化的核心裁定，也是它与 AGG §B.4.1 中"每段仍是独立 XSEG 节"表述的分叉点：
多节方案已被 `span64_hole` 反证（顺序分配不保证相邻），本设计不再走多节。
若未来引入"可重定位的分段描述"（llc 发相对偏移段表、lld 重写地址字段），本裁定
须重新评估；该方向属格式变更，不在本稿范围。

### 2.3 单条 v1 记录原理上装不下 65536

记录 v1（XDATA-CODE-DESIGN-SUPPLEMENT §7.3 冻结表）：`object_size` u16，语义
1..65535；`validateXDATAInit:3853` 明确 `!ObjectSize` 非法（0 不可当逃逸值）。
旁证（探针 `big65536/`）：把 65535 对象补丁成 65536 节后，其记录仍只覆盖 65535 B——
即使绕过尺寸门，单条 v1 记录也无法描述第 65536 个字节。
另：`LinkerCore.cpp:3830` 冻结契约句"**The linker never synthesizes XDATA_INIT
bytes**"——形态 (b) 需显式修订此句（修订措辞见 §6 D4，采评审精确句式）。

### 2.4 walker 天然支持多条记录

`validation/mcs251-elf/runtime/crt-xdata-init-walker.asm`（头注 + `:60-135` 循环体）：
驱动量是 `l_XDATA_INIT`（表总字节数），循环为"读 7 字节头 → DPXL/DPH/DPL 装载 →
清零或复制 → 回到下一条记录"的**平面记录流**，无任何每对象状态。多条记录本就是
原生模型（每对象一条只是当前 llc 的发射习惯）；`inc dptr` 无 bank 进位的前提
（记录保证单窗）由 lld 门与合成算法共同维持。⇒ **形态 (b) walker 零改动、
记录格式零重冻、`crt-selfstart-v2.yaml` 金样不动**。
输入侧同构旁证（§2.7.4）：现行 validator 本就接受"同一对象多条记录恰好覆盖"
的输入形态（`ctrl-exact` 探针 rc=0，输出字节逐一核对）——多记录消费路径是活的。

### 2.5 物理连续论证（r2 重写：两个命题分别给证）

`span64_hole`（AGG §B.4.1）证明的是：**两个独立 XSEG 节**经顺序分配器放置时，
若第二节在窗尾容不下，游标跳下一 bank 起点，两节不相邻。该反证的前提是
"逻辑对象 = 多个节"。本方案中逻辑对象**只有一个节**，反证前提不存在。
"大对象物理连续"完整论证拆为两个独立命题（评审 1a）：

**命题 A（地址区间内部无洞）**——由放置构造给出，构造性成立：

- A1 单节单区间：带标志节只走一次放置分支（`Place = XsegCursor`，跳过
  :2998 尺寸门与 :3020-3029 bank-jump），得到唯一区间 `[Place, Place+Size)`
  （:3037 `S->Address = R.Start`）；节内没有任何"片段"概念，符号地址即区间首地址。
- A2 区间内无对齐缝：结构性不可能——llc 层 `align 2` 的 AS3 全局即拒
  （`storage must be byte-aligned`，冻结负例 `xdata-placement.ll:107`，r2 实测复现）；
  lld 层 ALLOC 节的有效对齐必须为 1：`sh_addralign` 先在载入处归一化
  （`Align = max(1, sh_addralign)`，`LinkerCore.cpp:975`——**原始值 0 归一化为 1
  后放行，不是拒绝**；r3 措辞修正），随后 `Align != 1` 即拒
  （`:1038-1039`，r2 实测：补丁 XSEG 节 `sh_addralign=4` →
  `ALLOC section alignment must be 1`）；放置循环（:2991-3041）不含任何对齐代码。
  相邻零填充有实测样形：`recpair` 图 `_r1a [0x10000,+0xffff)` 与 `_r1b [0x1ffff,+1)`
  字节相邻（§2.7.2）。
- A3 切分只发生在放置完成后的**记录描述层**，不回写地址。

**命题 B（最终布局可容纳 demo 85 的 `0x21000`）**——依赖三个外部量：
XSEG 起始相位、前置 XSEG 对象集合、容量口径（`--xdata-size` / 板级跨度）。
这是**对目标产品实现的验收命题**：数学推导已闭合设计层（§2.7.3 解析推导给出
可行相位集合），实测矩阵为产品验收复核（评审 1d/1f；r4 措辞修正）：

- B1（现行等价形态实测，`r2rev/` 探针）：65535+1+65535+1+4096 五节在
  `--area-start=XSEG=0x010000` 下零洞、`l_XSEG = 0x21000`、`--xdata-size=0x21000`
  rc=0（§2.7.3 矩阵行 1）；
- B2 相位依赖性：同一节集仅当起始相位低 16 位 ∈ {0x0000, 0x0001} 时零洞通过——
  该"当且仅当"有解析推导（§2.7.3，限该五节顺序、无逐节覆盖起点、非地址空间顶端
  三前提），9 行实测矩阵为复核；其余相位因 bank-jump 洞被容量门拒绝（§2.7.3）——
  **"任意起始相位都可容纳"不成立**，demo 85 依赖板级固定相位 `0x010000`
  （`drive.py AREA_ARGS`）；

#### 2.7.1 AllSections 中 XSEG 节的排序规则（评审 1b）

- **规则**：`AllSections` 按 **命令行文件顺序 × 文件内 ELF 节表顺序** 构建
  （`run()` `LinkerCore.cpp:4511-4518`，逐文件把 `IsAlloc` 节按节表序追加）。
  **无任何按尺寸/名字的排序**——全文 14 处 `sort` 调用（:1424,2302,2545,2556,2955,
  3615,3887,4002,4088,4233,4260,4274,4293,4390）均在其他向量上（重定位偏移、
  记录目的区、位槽、警告表等），无一作用于 `AllSections`。XSEG 放置循环
  （:2991）按该顺序线性消费。
- **稳定性**：同一命令行下确定且可复现（实测两次链接输出 ELF 与 map 逐字节相同）；
  但**不按"大对象优先"排列**——前置节的尺寸决定大节的起始相位。
- **大对象前后插入其他 XSEG 节的行为（实测）**：`r2rev` 中 3 字节 `pre.o` 与
  demo 形状五节集互换个序：
  - `pre.o demo-set.o`：`pre [0x10000,+3)` 使 r1a 窗尾余量 0xFFFD < 0xFFFF →
    bank-jump 到 `0x20000`，留洞 `[0x10003,0x20000)`，`l_XSEG = 0x31000`；
  - `demo-set.o pre.o`：五节零洞占满 `[0x10000,0x31000)`，`pre` 落 `0x31000`，
    `l_XSEG = 0x21003`；
  - 两者在 `--xdata-size=0x21000` 下均 rc=1（前者洞推移容量、后者尾部 3 字节越门）。
- **设计决定**：S2 保持输入顺序、不引入尺寸排序（对既有全部链接零漂移是本方案的
  核心收益）；大节相位因此**由输入顺序决定**，其可行性归入命题 B 与 §5 矩阵管理，
  不在放置器内做隐式重排。

#### 2.7.2 节间对齐与 padding（评审 1c）

- 节间：所有 XSEG 节 `Align==1`（载入门 :1038-1039 硬拒有效对齐非 1），放置循环无对齐
  逻辑 → **零 padding**。实测：`recpair`/`r2rev` 图中相邻节首尾相接
  （`_r1a` 区间 `[0x10000,0x1ffff)` 的末字节为 `0x1fffe`，排他上界 `0x1ffff` 即
  `_r1b` 首地址——r3 措辞修正；`demo-set.o pre.o` 中 `xRAM3`
  末字节地址 +1 = 后节 `pre` 首地址（`0x30fff` + 1 = `0x31000`，r4 措辞修正）
  ——`l_XSEG=0x21003` 恰为逐字节累积）。
- 大节前：同理无 padding；大节起始地址 = 前置节末字节 + 1（任意相位，含非整窗）。
- 双层封口：llc `align 2` → `__xdata global 'a': storage must be byte-aligned`
  （r2 复现 rc=134）；lld `sh_addralign=4` 补丁节 →
  `ALLOC section alignment must be 1: .mcs251.XSEG._pre`（r2 实测 rc=1）。

#### 2.7.3 `--area-start=XSEG` 起始相位 × 精确容量 `0x21000` 矩阵（评审 1d/1f）

节集 = demo 形状复刻（65535+1+65535+1+4096，总 `0x21000`），`--xdata-size=0x21000`：

| 起始相位 | rc | 布局摘要 |
|---|---|---|
| `0x010000` | **0** | 零洞：`[0x10000,+0xffff) [0x1ffff,+1) [0x20000,+0xffff) [0x2ffff,+1) [0x30000,+0x1000)`；`l_XSEG=0x21000` |
| `0x010001` | **0** | 零洞：`[0x10001,+0xffff) [0x20000,+1) [0x20001,+0xffff) [0x30000,+1) [0x30001,+0x1000)`；`l_XSEG=0x21000` |
| `0x010002` | 1 | r1a 窗尾余量 0xFFFE < 0xFFFF → 跳 `0x20000`；洞使 r2a 落 `[0x30000,0x3ffff)`，容量门拒（`exceeds --xdata-size=135168`） |
| `0x010004` / `0x010005` / `0x018000` | 1 | 同上（洞推移，r2a 越容量门） |
| `0x01fffe` / `0x01ffff` | 1 | xRAM3 跳至 `[0x40000,0x41000)`，容量门拒 |
| `0x020000` | **0** | 整集平移一窗，零洞；`l_XSEG=0x21000`（容量门相对 `Base` 计，不约束板级窗口——板级约束是 `drive.py` 钉相位的原因） |

结论：**精确容量可行性是相位的函数**，本节集下当且仅当相位低 16 位 ∈
{0x0000, 0x0001} 时通过；demo 85 的板级相位 `0x010000` 在其中。

**解析推导（r3 补齐，评审 #2-a；r4 修正两处数学错误：洞长不等式 + p=1 基址统一；
结论不再依赖抽样实测的"当且仅当"表述）**：
设 `B` 为 XSEG **实际基址**（低 16 位 `p = B & 0xFFFF` 为相位；全文只用 B，
不另设窗对齐基址符号），五节顺序
`s = (65535, 1, 65535, 1, 4096)`，总量 `0x21000 = N`，顺序放置 + 跳窗规则
（:3020-3029：`Size > 窗尾余量` → 游标跳下一窗起点）。记 `[B, B+N)` 为相对窗口。

- **必要性（p ≥ 2 ⇒ 必有正长度洞 ⇒ 必拒）**：首节零跳变要求窗尾余量
  `0x10000 − p ≥ 65535`，即 **`p ≤ 1`**。`p ≥ 2` 时 s1 跳窗，留下的洞长
  `= 0x10000 − p`；由 `2 ≤ p ≤ 0xFFFF` 得洞长 `∈ [1, 0xFFFE]`，恒为正
  （r4 更正：原稿"≥ 0xFFFE"把上界误作下界——0xFFFE 是 p=2 处的**最大**洞长，
  p=0xFFFF 时洞长仅 **1 B**；1 B 洞同样必拒，与 §2.7.7 的 1 B 洞实测一致）。
  各节区间互不重叠（:3032-3036）且 Σ Size = N，故任一正长度洞直接累加到
  最大末界：`max(Hi) = B + N + (0x10000 − p) > B + N`，
  容量门（:3042-3058，`Hi > Limit` 即拒）必拒。逆否命题同样成立：
  **总量恰等 N ∧ 区间互不重叠 ∧ 容量门通过 ⟹ 相对窗口内零洞**。
- **充分性（p ≤ 1 ⇒ 零洞顺排；区间一律自实际基址 B 顺排，r4 统一）**：
  `p = 0`：s1 `[B, B+0xFFFF)` 余 1 → s2 `[B+0xFFFF, B+0x10000)`，游标恰落第二窗
  起点；s3 `[B+0x10000, B+0x1FFFF)` 余 1 → s4 `[B+0x1FFFF, B+0x20000)`；s5
  `[B+0x20000, B+0x21000)`。首地址即 B，尾界 `= B + N`，零洞。
  `p = 1`：s1 窗尾余量恰等 `0x10000 − 1 = 0xFFFF` → `[B, B+0xFFFF)`，游标
  `B+0xFFFF` 恰为第二窗起点；s2 `[B+0xFFFF, B+0x10000)`，游标 `B+0x10000`；
  s3 余量恰等 0xFFFF → `[B+0x10000, B+0x1FFFF)`，游标 `B+0x1FFFF` 恰为下一窗
  起点；s4 `[B+0x1FFFF, B+0x20000)`；s5 余量 `0xFFFF ≥ 4096` →
  `[B+0x20000, B+0x21000)`。首地址即 B，尾界 `= B + 0x21000 = B + N`，零洞。
  数字例（`B = 0x10001`）：五节依次 `[0x10001,0x20000) [0x20000,0x20001)
  [0x20001,0x30000) [0x30000,0x30001) [0x30001,0x31001)`，首地址即 `0x10001`、
  尾界 `0x31001 = B + N`——与 r3rev 第 6 节 `0x010001` 实测尾界一致
  （r4 更正：原稿此分支误按窗对齐基址 +1 展开，首末地址整体多 1 且与
  "尾界 = B+N"自相矛盾）。
- **前提限定（结论仅在该形态下成立）**：(i) 该五节顺序（其他顺序/尺寸需重推）；
  (ii) 无逐节 `--area-start` 覆盖起点（覆盖直接改写各节起点与余量）；
  (iii) 非地址空间顶端溢出（顶端跳窗走 `rangeFits` :3030 拒绝，非容量门路径）。
- 独立复核：评审侧对全部 65536 相位做独立内存模拟（按 :3026-3028 规则），通过
  集合同为 {0, 1}；r4 侧同款全相位模拟进一步确认对全部 p ≥ 2 洞长恰等
  `0x10000 − p`（范围 [1, 0xFFFE]），与更正后的不等式一致；上表 9 行实测一致。
  推导是结论来源，实测是复核。

**"相对可行"≠"板级合法"（r3 实测，G-T4 前提的动机）**：上表均为相对窗口
`[B, B+N)` 内的判定。板级合法窗口是 `[0x010000, 0x031000)`。相位 `0x010001`
在相对口径下 rc=0（尾界 `0x031001 = B + N`），但已越板级窗 1 B——r3rev 第 6 节
实测：`0x010000` 尾界 `0x31000`（恰等）、`0x010001` 尾界 `0x31001`（越 1 B），
两者相对容量门都通过。板级合法性由 §5 G-T4 前提清单约束，不能以
"相位落在可行集合"替代。65536 单对象形态（无 bank-jump、允许跨窗）的相位矩阵
属 S3（G-T11-MAIN）：预期任意相位零洞（单区间放置不产生跳变），但该预期在 S2
落地前为**未证实**。

的角色是：现行基线测量 + S2 放置/合成语义的开发输入；**S3 正式矩阵必须用真实
S1 llc 输出重生成后执行**（§4/§5）。

G-T11-MAIN 24 组合在**现行产品**上的实测（r3rev 第 2 节）：**24/24 rc=1**，

- 逐节钉置跨窗检查独立触发：65535 节钉 `0x01ffff` →

- 顺序放置不跨窗但可顶到窗尾：65535 节在相位 `0x010001` 顺序放置 →
  `[0x10001,+0xffff)` 零跳变落位（余量恰等）。

⇒ §3.1.3 的跨窗不变量在现行产品上**无一可执行**（BASE 套件被尺寸门拦截、
MAIN 套件被 flags 门拦截）；它们是 S2 实现与 S3 矩阵的规约，不是现状描述。
G-T11-MAIN 的 24 组合在 S2 后转为正例语料（**S2 解锁 = llc 发标志 + lld 白名单
两件齐备**；只完成 S1 时现行 lld 仍按 unknown-flags 拒绝——r4 命名修正），
正例断言含记录数预期（§3.1.3 推导表）。

#### 2.7.6 G8 EDATA relayout 不迁移 XSEG（评审 1e，升级为已验证不变量）

**不变量 INV-XSEG-STATIC：G8 失败回退重布局不读写任何 XSEG 节的地址。**
证据（`LinkerCore.cpp:2714-2844` 全函数审读 + 全文件地址写入点普查）：

- 迁移候选集只来自 `Region == "DSEG" && EDataMovable && Size != 0`
  （:2737-2739，`EDataMovable` 由 G8 标志位在分类时设置，:474）；
- 重布局循环只对三类节写地址：直接 EDATA 节（:2788-2791）、未迁移 DSEG 节
  （:2794-2796）、OSEG 覆盖组（:2801, tryOverlayGroup :2750-2766）；
- 全文件 `S->Address =` 写入点普查（15 处）：XSEG 节的地址**只**在 XSEG 放置循环
  :3037 写入；其余写入点分别属符号解析（:1631/:1633/:1646/:2245/:3200/:3202）、
  layoutCode 六区域（:2392）、合成 XINIT（:2602）、DATA_ABS（:2643）、REG（:2673）、
  覆盖组（:2692/:2764）、ISEG（:2869）、SSEG（:2977/:2981）——无一触及

#### 2.7.7 大对象间中插交互矩阵（r3 新增，评审 #1：中插 × 小节尺寸覆盖）

r2 只实测了前置/后置 3 B 两种实例，未覆盖"大对象之间插入其他节"与不同小节
尺寸。r3rev 第 4 节补齐：基序列 o1..o5 = (65535, 1, 65535, 1, 4096)
（总 `0x21000`），插入节 ∈ {3 B, 128 B, 65535 B(=64K−1)}，插入位置 ∈
{s1 后, s2 后, s4 后}，基址 `0x010000`。每格跑两遍：无容量门取布局视图
（map 解码洞与尾界），带 `--xdata-size=0x21000` 取门判定。实测（`mapx.py`
解析；`l_XSEG` 为含洞跨度）：

| 插入（尺寸×位置） | 门判定 | 失效模式 | 洞（布局视图） | 尾界 | `l_XSEG` |
|---|---|---|---|---|---|
| 基线（无插入） | **rc=0** | —— | 无 | `0x31000` | `0x21000` |
| 3 B × s1 后 | rc=1 | 洞推移 | `[0x1ffff,+1)` + `[0x20004,+0xfffc)`（共 65533 B） | `0x41000` | `0x31000` |
| 3 B × s2 后 | rc=1 | 洞推移 | `[0x20003,+0xfffd)`（65533 B） | `0x41000` | `0x31000` |
| 3 B × s4 后 | rc=1 | 尾部越门 | 无 | `0x31003` | `0x21003` |
| 128 B × s1 后 | rc=1 | 洞推移 | `[0x1ffff,+1)` + `[0x20081,+0xff7f)`（共 65408 B） | `0x41000` | `0x31000` |
| 128 B × s2 后 | rc=1 | 洞推移 | `[0x20080,+0xff80)`（65408 B） | `0x41000` | `0x31000` |
| 128 B × s4 后 | rc=1 | 尾部越门 | 无 | `0x31080` | `0x21080` |
| 65535 B × s1 后 | rc=1 | 洞推移 | `[0x1ffff,+1)`（1 B） | `0x41000` | `0x31000` |
| 65535 B × s2 后 | rc=1 | 洞推移 | `[0x2ffff,+1)`（1 B） | `0x41000` | `0x31000` |
| 65535 B × s4 后 | rc=1 | 洞推移 | `[0x3ffff,+1)`（1 B） | `0x41000` | `0x31000` |

两种失效模式实测分离（r3 修正"额外字节必然击穿零余量"的单一叙事）：

- **洞推移**（7 例）：插入使后随 65535 节的窗尾余量不足 → 跳窗留洞 → 洞把
  后续节推向高窗 → 容量门拒（报文如 `XDATA capacity [0x30000,0x3ffff) exceeds
  --xdata-size=135168`）。洞可极大（小节顶掉整窗余量，~64K）也可仅 1 B
  （65535 节插在窗边界）——1 B 洞同样击穿零余量，与 I2.2"洞消耗容量预算"
  一致。
- **尾部越门**（2 例：3 B/128 B 插在 s4 后）：插入落在末窗且不触发跳窗，零洞，
  尾界直接越 `0x31000`（`0x31003`/`0x31080`）。

含义：零余量场景的"额外 XSEG 字节必拒"成立，但**失效模式由插入位置决定**，
两种模式的门报文同为容量拒绝，判别须依赖布局视图（洞存在性 + 尾界），不能
只看 rc。基线行同时复现了 §2.7.3 行 1（零洞、尾界恰等）。

#### 2.7.8 合成输出布局门的现行机制取证（r3 新增，配合 §3.1.2 第 3 条与 G-T13）

三道门涉及的全部机制在现行产品均已存在并可独立触发（r3rev 第 5 节实测消息）：

## 3. 方案空间

### 3.1 方案 A（推荐）：形态 (b) 工程化 —— lld 放置后合成 clear-only v1 记录

改动面 = llc 门放宽（限全零初值）+ 1 个节标志（**绑 v2 producer capability**，
见 D3）+ lld 放置分支与记录合成。
**记录格式、walker、CRT、金样全部零改动。**

#### 3.1.1 llc 侧（记录发射）

位置：`MCS251AsmPrinter.cpp:2277-2280` 及 AS3 发射块 `:2268-2309`。

1. 门改为：

   ```
   若 Size > UINT16_MAX：
     - 初值非全零（HasPayload）→ 仍 Bad（文案改为 "payload cannot exceed the
       16-bit XDATA record limit (65535 bytes); zero-initialized objects are
       split by the linker into per-window records"）
     - 初值全零 → 放行，XSEG 节加标志 SHF_MCS251_XSEG_SPLIT（0x40000000，
       下一位，G8 同款模式：ELF.h 常量 + lld 常量双处），**跳过 :2298-2304 的
       记录发射**（单条 v1 装不下，见 §2.3），其余发射不变（NOBITS 节、
       emitLinkage、emitELFSize、字节对齐门、isSupportedMutableInitializer 门照旧）
   若 Size ≤ UINT16_MAX：现行路径**一字节不变**（记录照发、无标志）
   ```

   > 刻意收窄：≤65535 的全零对象**不**加标志、**不**改由合成——现有对象与全部
   > 既有 fixture 的字节流零漂移，金样不重冻是本方案的核心收益。
   >
   > 版本绑定（D3 裁定，采 G8 机制）：带标志节仅对 **v2 身份对象**（e_flags
   > `ABI_FLAGS_V2`）发射。生产流已是 v2 身份（实测 `/home/liu/build-mcs251/bin/llc`
   > 对本形态输出 `0x102`）；lld 侧对 v1 对象携带该标志硬拒（§3.1.2 第 1 条）。

2. `:2225-2230` 的 AS3 注释（"XSEG objects never straddle a 64K window;
   >64K single objects are out of profile"）同步改写为两态表述：
   无标志节维持单窗裁定；带标志节是**逻辑大对象**，允许跨窗、由 lld 按窗切分描述。

#### 3.1.2 lld 侧（分类 / 放置 / 合成 / 校验）

1. **分类**（`classifySection` :627-634 XSEG 分支内扩展）：`.mcs251.XSEG` 前缀且
   flags == `ALLOC|WRITE|SHF_MCS251_XSEG_SPLIT` → `Region="XSEG"` +
   `S.XsegSplit=true`；**身份门**：仅 `S.File->EFlags == ABI_FLAGS_V2` 接受该位，
   v1 对象携带 → 硬错误（措辞仿 G8 `:555-560` "carries the ... flag outside its
   v2 contract"）；`Common` 掩码（:483-485）加入该位。
2. **放置**（XSEG 循环 :2991-3041）：

   ```
   带标志节：
     - 跳过 :2998 的 Size > 0xffff 硬拒；
     - 跳过 :3020-3029 的 bank-jump 分支（Place = XsegCursor，单区间连续放置，
       §2.5 命题 A 的构造性连续）；
     - 显式逐节 --area-start 仍按字面执行，但豁免 :3011-3019 的跨窗检查
       （跨窗是该节的本意；24 位 rangeFits :3030 / 容量门 :3042-3058 /
       重叠门 :3034-3036 照常适用）；
   无标志节：现行逻辑一字节不变（含 65536 拒绝——负例保留）。
   ```

3. **合成**（插入点：`layoutData` 内 XSEG 循环与容量门之后、:3074 的 `s_/l_`
   Synth 之前；此时全部 XSEG 地址已定，`layoutCode`（:3225 `layout = layoutCode
   && layoutData` 的前半）已把 XDATA_INIT 输入节排完）：

   ```
   对每个带标志且 Size>0 的 XSEG 节（按 AllSections 顺序）：
     cur = S.Address; remaining = S.Size;
     while remaining:
       len = min(remaining, 0xFFFF, windowEnd(cur) - cur)   # 单窗 + u16 双约束
       追加 7 字节 clear-only 记录：(cur>>16, cur&0xFFFF, len, 0)
       cur += len; remaining -= len
   合成产物 = 一个合成 InputSection{Region="XDATA_INIT", Data=记录字节,
   IsLoadable=true, Synthesized=true}
   ```

   **r3 阻断修正（评审第二轮新增项）：合成表的 ROM 布局不是"接在最后一条输入
   记录之后、地址无冲突"的隐式推论。** XDATA_INIT 游标尾部之后可能已无空隙
   ——其他 CODE 区（CSEG/XINIT/BOOT 等）可以从任意方向顶进来，游标尾部也可能
   越过 24 位上界；只写 Image 或只检查 XDATA 目的记录都不能替代 CODE 账本检查。
   因此合成节放置必须**显式走既有 CODE 预留机制**（先例：常规路径
   `reserveCode` :2351-2359 定义、:2390 调用；XINIT 位段合成已在 :2614 显式
   调用），即插入点执行顺序固定为：

   - **G3（缺 XDATA_INIT 起点拒绝）**：合成点自查
     `if (!hasAreaStart("XDATA_INIT")) fail("missing --area-start=XDATA_INIT")`。
     不能依赖 layoutCode 的同名检查（:2376-2382）——它只对**存在的输入节**
     生效，S1 语义下仅含带标志对象的链接没有任何 XDATA_INIT 输入节（§2.7.8
     G3 行）；先例：XINIT 位段合成 :2579-2582。
   - **G1/G2（CODE 重叠 / 24 位边界拒绝）**：显式
     `reserveCode(Start, Size, Name)`——G1 `CODE overlap for ...`（CodeUsed
     相交即拒）、G2 `CODE address overflow in ...`（`rangeFits`）由该调用免费
     获得，与常规 CODE 节和 XINIT 合成走同一账本；现行消息实测见 §2.7.8。
   - 通过后按 XINIT 位段同款把字节写入 Image（逐字节重复检查，:2616-2622
     先例；layoutCode 的 `duplicate CODE byte` :2398 同账本兜底），并把合成节
     追加进 AllSections；
   - :3074-3081 的 `s_/l_XDATA_INIT` Synth 自动计入（合成节 `Address+Size`
     参与取最大端）；
   - `validateXDATAInit`（:3832）按输入节同一循环**统一校验**合成记录
     （单窗 :3864、WithinOneSlice :3869-3880——合成记录是所在大节的子区间，
     判定天然通过；不重叠门照走）。

   **三门与 SM4 的组合顺序（r3 明确）**：① `layoutCode` 放置输入 XDATA_INIT
   （常规 `reserveCode`，:2390）；② XSEG 放置循环 + 容量门（:2991-3058）；
   ③ 合成点：G3 自查 → G1/G2 `reserveCode` → Image 写入（重复字节即拒）→
   追加 AllSections；④ `s_/l_` Synth；⑤ `validateXDATAInit`：结构/单窗/落节/
   不重叠对**全部**记录（输入 + 合成）生效；SM4 的"输入记录目的区间 ∩ 带标志
   节区间 = ∅"检查在逐记录扫描处执行（:3881 push 处比对），且**只对输入记录
   比对**——`L:3838-3881` 当前统一遍历所有 XDATA_INIT 节，实施时须按
   `S->Synthesized` 分流，否则合法合成记录（目的区间必然落在带标志节内）会被
   SM4 误拒。非法输入记录覆盖带标志节时 SM4 在扫描处即时整链接拒绝，与三门
   任意先发生者为准；全部通过后合成记录才存在于 Dests 集合中。任一 G 门或
   SM4 失败 → `fail()` 整链接拒绝，无降级路径。**负例组 G-T13（新增，§5）**：
   三门各配独立负例（S2 后执行；现行机制取证 r3rev 第 5 节）。

   **合成器专属覆盖不变量（评审 3）**：对每个带标志节，合成记录集合的目的区间
   **并集恰等于 `[S->Address, S->Address+Size)` 且两两不交、顺序衔接**
   （`cur` 从 `S->Address` 起按 `len` 严格推进到 `S->Address+Size`，由构造给出）。
   这是**合成器的构造性质，不是 `validateXDATAInit` 的保证**（validator 实测
   接受欠覆盖/缝隙/错起点输入，§2.7.4）。负例清单（全部为现行 validator 的
   "盲区"，S3 固化为 lit 级负例时须由**合成路径自身的自检断言或字节比对测试**
   承接，不能指望既有校验拦截）：

   | 负例 | 形态 | 现行 validator 结果（实测） |
   |---|---|---|
   | 缺首段 | 首记录从 `S->Address+1` 起 | rc=0（`miss-head`） |
   | 缺中间段 | 第 k 条尾与第 k+1 条头间留缝 | rc=0（`gap-mid`） |
   | 缺尾段 | 末记录止于 `S->Address+Size-1` | rc=0（`miss-tail`） |
   | 错误起点 | 整体偏移 1 B、无缝隙 | rc=0（`wrong-start`） |
   | 错误长度 | 记录长度和 < Size（欠覆盖） | rc=0（`short-total`） |
   | （对照）越节 | 覆盖超出节区间 | rc=1（WithinOneSlice 拒，`over-slice`） |

   `recpair` 探针给出了 demo 85 对象集下合成结果的目标样形（逐字节实测，
   含输出 ELF 解码）：

   ```
   01 0000 FFFF 0000   → 清零 [0x010000, 0x01FFFF)
   01 FFFF 0001 0000   → 清零 [0x01FFFF, 0x020000)
   02 0000 FFFF 0000   → 清零 [0x020000, 0x02FFFF)
   02 FFFF 0001 0000   → 清零 [0x02FFFF, 0x030000)
   03 0000 1000 0000   → 清零 [0x030000, 0x031000)
   l_XSEG = 0x21000；--xdata-size=0x21000 rc=0
   ```

   （该样形当前由"65535+1 源级尺寸"复刻；形态 (b) 落地后同样布局由
   `2×65536 + 4096` 单对象直接产生。**注意：recpair 只证明记录样形与现行
   容量门/校验器行为，不证明产品放置器对带标志大节的放置语义**——后者由
   §3.1.3 不变量与 §5 G-T11 矩阵约束。）

4. **防滥用/一致性门（非零初值拒绝的完整状态机，评审 6）**——带标志 XSEG 节
   `S` 合法当且仅当以下四条**全部**成立；任一不满足即**整链接拒绝**
   （`fail()`，非警告、无降级路径）：

   | # | 条件 | 机制位置 | 独立负例（S3 固化） |
   |---|---|---|---|
   | SM1 | 名匹配 `.mcs251.XSEG` 前缀 | 分类既有规则（:627） | 非 XSEG 名带标志 → 落入"unsupported ALLOC section"既有拒绝 |
   | SM2 | `S.Type == SHT_NOBITS` | XSEG 形状检查（:628-630 扩展） | PROGBITS+标志 XSEG 名 → "XSEG must be writable NOBITS" |
   | SM3 | `S.Flags == ALLOC\|WRITE\|SHF_MCS251_XSEG_SPLIT`（逐位精确） | 分类分支 + Common 掩码（:483-485 扩展） | 少 WRITE、多 OVERLAY、未知位 → 既有 flags 拒绝 |
   | SM4 | "零初始化"的链接期可检形态：**无任何输入 XDATA_INIT 记录的目的区间与 `[S->Address, S->Address+Size)` 相交** | `validateXDATAInit` 的 Dests 集合上新增检查（:3881 push 处比对） | 带标志节 + 输入记录覆盖其任意字节（首/中/尾各一负例）→ "input XDATA_INIT record covers split-XSEG section"硬错误 |

   说明：SM4 是"零初始化"在 lld 侧唯一可观测的充分条件——非全零初值对象由
   llc 发记录（llc 侧门 §3.1.1 已拒其大对象形态），因此"有记录覆盖带标志节"
   只可能是手造 ELF 或 llc 门失效，两种来源都须整链接拒绝。SM1-SM4 与 D3 的
   v2 身份门（§3.1.2 第 1 条）共同构成五重防滥用；v1 对象 + 标志 →
   "carries the split flag outside its v2 contract"硬错误（G-T10 负例）。
   `:3830` 契约句修订见 §6 D4。

#### 3.1.3 跨窗放置语义：实现不变量与负例矩阵（评审 2）

带标志大节的放置不是"跳过一个 if"，以下不变量逐项列出，每项配负例；
**整个矩阵在 S2 落地前不可执行**（现行产品：无标志语料在尺寸门即拒、带标志
语料在未知 flags 门即拒，§2.7.5），recpair 类"65535+1 复刻"探针不构成对这些
不变量的证明：

- **I2.1 游标与区间更新**：`Place = XsegCursor`；放置后 `XsegCursor = R.End`
  （:3040）**允许落在任意相位**（跨窗推进）。后续无标志节的 bank-jump 判定
  （:3026-3028）以推进后的游标所在窗计算 `WindowEnd`，不得因前一大节跨界而
  错算窗尾或错跳。正例：大节 `[0x10001,0x20001)` 后随 65535 无标志节 → 应落
  `[0x20001,0x30000)`（余量恰等、零跳变）。负例（r3 修正：原例
  "`[0x1ffff,0x30000)` 后随 4096 节应跳窗"不成立——该大节末恰为窗 `0x03`
  起点，游标 `0x30000` 处余量 65536，4096 节直接放置 `[0x30000,0x31000)`，
  零跳变；跳窗负例改为）：大节 `[0x10001,0x20002)`（65537 B）后随 65535
  无标志节 → 游标 `0x20002`，窗 `0x02` 余量 `0xFFFE < 0xFFFF` → 跳 `0x30000`，
  洞 `[0x20002,0x30000)`（检验 WindowEnd 取推进后游标所在窗，而非大节起始窗）。
- **I2.2 `--xdata-size` 容量语义（r3 全文更正，评审 #6 第三组；r4 补下界）**：容量门按
  **整节区间** `[Lo,Hi) ⊆ [Base, Base+N)` 判定（:3042-3058，逐节、64 位算术，
  末界判定在 :3052），对跨窗大节无逐窗拆分、无窗数折算；大节通过当且仅当
  **`Lo ≥ Base && Hi ≤ Base+N`**（r4 补下界：允许逐节钉置时大节可落到 `Base`
  之下，如 `Base=0x10000`、大节钉 `0` 尺寸 65536，末界满足上界仍须按
  `Lo < Base` 拒——仅查上界会漏判）。负例：65536 节使 `Hi = Base+N+1` → 拒
  （文案同现行 `exceeds --xdata-size=`）；`Hi = Base+N` 恰等 → 过（现行门
  `Hi > Limit` 判定 :3052 的直接推论）。**洞的口径：门不单独求和洞长度，但洞确实消耗容量
  预算**——洞把后续节的 `Hi` 后移，零余量（ΣSize = N）且区间互不重叠时，任何
  正长度洞必把某节的 `Hi` 推过 `Base+N` 而被拒（§2.7.3 解析推导的逆否）。
  相位 `0x020000` 行通过**只说明 `Base`（从而 `Limit = Base+N`）随
  `--area-start` 参数平移，不说明洞不计入**。由容量门通过真正推不出的是
  "相对窗口 = 板级合法窗口"（r3rev 第 6 节实测：`0x010001` 相对通过、尾界
  `0x031001` 越板级 `[0x010000,0x031000)` 1 B）；板级合法性由 §5 G-T4 前提
  清单保证。中插矩阵（§2.7.7）的 1 B 洞拒例与洞推移 7 例是该口径的行为学
  佐证。
- **I2.3 符号与存储指针**：XSEG 定义符号终值 = 24 位 canonical 节首（与窗无关）；
  R_MCS251_24 存储指针门按**节区间 + one-past** 判定（:3497-3516，
  `[Lo, Hi]` 闭区间含 one-past），对大节即 `[base, base+Size]`——跨窗指针
  `base + 0x8000`、`base + Size`（one-past）合法，`base + Size + 1` 拒。
  负例：指向 `base+Size+1` 的静态指针 → "resolves outside the target object"；
  正例：`base+Size` one-past 哨兵 → 过。X2 三字节通道（HI8/MID8/LO8）范围检查
  （:3532-3541 Is24Slice）为 24 位有符号窗，与窗位无关——零改动。
- **I2.4 16 位通道**：R_MCS251_16/J16 命中 XSEG 定义符号仍硬拒
  （:3414-3424，判定按 Region，与节尺寸/跨窗无关）。负例沿用既有 lit 形态、
  目标换成大节符号即可。
- **I2.5 重叠检查**：`XDataUsed` 两两相交判定（:3032-3036）按节区间，大节与
  任何其他 XSEG 节（含显式钉置节）相交 → "XDATA overlap" 拒。负例：65536 节
  顺序放置后，一节钉置进其区间内 → 拒。
- **I2.6 逐节钉置豁免**：带标志节的显式 `--area-start` 跨窗不再触发
  :3011-3019；**无标志节的同款钉置跨窗仍拒**（现行负例保留，§2.7.5 实测）。

### 3.3 方案 B（对照）：形态 (a) —— XDATA record v2 + walker bank 进位

仅当需要**单条记录描述跨窗对象**（典型动机：非零初值 >65535，v1 的

1. **格式**：新节 `.mcs251.xdata_init2`（新 Region，与 v1 表并存、互不混写），

   `s_/l_XDATA_INIT2` 合成符号。
4. **walker v2**：新 BOOT 块（v1 walk 之后追加）；zero/copy 内循环加 bank 进位

   `lld/test/MCS251/{crt-v2,xdata-init}.test`、`mcs251-xdata-e2e` QEMU 金样。
5. **对比与定位**：

   | 维度 | 形态 (b)（方案 A） | 形态 (a) |
   |---|---|---|
   | 覆盖 | ≥64K **全零**对象（demo 85 全部需求） | ≥64K 任意初值对象 |
   | 记录格式 | v1 零变化 | 新 v2（9 字节头） |
   | walker | 零改动 | 新增 v2（bank 进位） |
   | 金样/fixture | **零重冻**（两个 HUGE 负例测试改为条件化保留） | CRT 两 YAML + lld 三 test + QEMU e2e 重冻 |
   | 新增概念 | 1 个节标志（v2-only）+ 合成规则 | 新记录节 + 新 walker + 新区域符号 |
   | 规模估计 | 2-3 人日 | 8-13 人日（参照 DF4 §13.2 粒度） |
   | 关系 | 可先行；v2 到来后合成记录仍走 v1 表 | 独立立项，不阻塞 (b) |

   ⇒ (a) 不是 (b) 的替代，而是**超集能力**的独立增量。demo 85 与语料扫查
   （AGG §A.4.2/§B.3.2：≥64K 需求仅 demo 85 的两个全零数组）不构成 (a) 的立项压力。

### 1.2 不重开的已批准事项（I §1.1、§2、§5、§8.3、§9.5）

1. 唯一语言入口为 `__attribute__((interrupt(N)))`，首期不做官方库兼容。
2. ISR 独立 CC、硬件入口身份和 RETI；不是普通 Far24 函数的变体。
3. 每次入场保存直接下层完整整数现场；设计保存量为每层 **37B**。
4. 固定 bank 0／DPS 0，固定初始优先级，支持不同档位及严格高打断低。
5. 首期普通档位设计基线为 0–3；排除 NMI／T0 mode3。
6. ISR 普通辅助闭包保持同模块、直接可解析、本地绑定、无静态参数槽、Far24。
7. A 线 ISR 闭包检查与 B 线全映像可抢占 SPX 检查均必须闭合。
8. 链接器生成唯一完整向量表，默认入口 fail-stop。
9. 动态 ISR 帧、任意跨 TU 闭包、运行时优先级便利接口不进入首期。

### 1.3 核对后需要显式计入排期的三个前置缺口

**第一，ELF v2 公共底座尚不能按"已经具备"计。** 当前发射器仍生成 v1 note、E3 读取器按 v1 身份校验（`MCS251ELFStreamer.cpp`、`lld/MCS251/LinkerCore.cpp`）。Tiny/XTiny 的内部数值契约不能替代对象协议 v2。中断生产链必须补足已批准的 v2 身份载体及所使用的函数、site、安全、栈子协议；不得临时扩写 v1。依据 D F.2/N.8–N.9、E 运行时修正案第 7 条。

**第二，ISR 所需 GC 不是当前 E3 已有能力。** E 的现有运行时集成规范仍排除 GC／archive；I §4.3、§9.2、§10.1 要求注册保活与 GC 验收。推荐增加**受限 section GC**，但不顺带纳入 archive 懒提取、ICF、COMDAT 或 LTO。

**第三，现有算术运行时不是 ISR-safe 库。** 其静态参数槽决定它不能直接进入 ISR 闭包。只在主程序使用时，也仍需满足 B 线和对象版本要求；当前 v1 库不能直接混入新的 v2 中断映像。依据 I §7.2–§7.3、D D.5、E 运行时修正案第 2、3、7 条。

## 三、建议 PM 按此方向冻结的技术方案

### 3.1 数字登记和版本策略

一次登记包涵盖：LLVM／Clang CC 及文本拼写；普通 Far24、硬件 IRQ、不可返回 IRQ 终止入口、受控启动入口的身份关系；硬件帧 profile 与保存 profile；函数／site、安全／栈、向量注册、配置关联子协议版本；对应能力位；元数据符号引用 relocation。

**不因添加 interrupt 属性改变普通函数参数 ABI。**D 已冻结的 attributes 信封、Tag 编号、Critical 规则保持不变；新增字段用新登记 Tag，不复用 reserved0–2，不偷偷改变 v1。

### 3.2 对象记录推荐形态

**固定字段、显式版本和长度的二进制记录**，不嵌自由 JSON／字符串协议。

| 记录 | 必需表达 |
|---|---|
| 统一入口记录 | 精确函数入口关联、代码范围、入口种类、调用签名／返回契约；IRQ 的硬件帧与保存 profile |
| 向量注册记录 | 槽号、IRQ 入口关联；不存可独立生效的 priority |
| A 线闭包记录 | 根关联、检查协议、闭包完成状态、最终调用依赖；未知原因不能编码为成功 |
| B 线 SPX 记录 | 函数／代码范围关联、安全状态、检查协议；启动资产使用独立资格种类 |
| 固定栈记录 | 自身固定上界、上界有效性、最终普通调用边及帧契约；根摘要给出可核验的 K/W |
| 配置／资产记录 | 数值配置摘要、检查协议、CRT／终止资产身份与版本 |

共同规则：①标量采用 ELF 目标大端，长度／范围／数量先做不溢出校验；②**安全状态和数值分开**（"未知""已知下界""完整上界""应用预算声明"不能靠同一整数约定值区分）；③统一带符号引用记录+明确关联 relocation，不得借用函数指针 relocation 假装 ISR 可取地址、不占用保留编号 19；④记录 section 非 ALLOC，属性 section 继续禁 relocation（E3 需为元数据 section 增加窄范围处理路径，不是整体放宽）；⑤ISR 入口引用必须精确落在入口；local symbol 折成 section+addend 后仍须能恢复同一身份；⑥GC 只由注册记录等真正根产生保活；⑦首期不支持修改后无法重建摘要的 LTO、ICF、部分链接及对象重发射，明确拒绝；⑧可信边界是受支持工具链，不把元数据当密码学证明。

**B01 退出必须包含完整字段偏移、大小、枚举值、关联 relocation、重复／缺失规则和至少一组原始字节 fixture。**

### 3.3 数值配置与 CLI 推荐

构建层生成**版本化、仅以数值承载目标语义的规范 JSON**（稳定字段名；不以器件名称、"high"/"low" 等值驱动目标语义）。

- 构建变量：`IRQ_CONFIG`（合成后数值描述）、`IRQ_MAIN_STACK_BUDGET`（已规范化、从 B 计量的 M）
- Clang driver：`-mcs251-interrupt-config=<absolute-path>`；linker：`--interrupt-config=<absolute-path>`（**建议拼写，非当前已支持命令**）
- cc1／llc 实际接收冻结的数值字段、协议及配置摘要，不直接读板 Makefile；原有 `--stack-size` 继续表示原 SSEG 语义，不改名复用为 M

冻结规则：所有有效槽显式 priority；`initially_enabled` ⊆ `may_enable`；可能使能源必须有合法注册/默认入口及完整开销；每个优先级／使能映射分别指定寄存器、位、有效／保留位、共享关系；启动写入计划由同一描述生成（不做多 TU last-wins）；第一版保守失效策略（配置变化→相关 IR／对象／CRT／最终链接重新生成）；配置摘要与最终构建清单摘要分两层（前者不含产物自身哈希避免循环）。

### 3.4 两个容易被遗漏的编译器约束

**保活根不是源程序取地址许可**：通过 LLVM 真实保活机制保护 ISR，verifier 仅允许受控注册／保活用途，仍拒绝普通 C 取地址、指针转换和调用。

**固定优先级检查不能声称识别任意整数指针**：已知非初始化优先级写入必须报错；未知控制状态／SPX 副作用按保守规则处理；AS／SFR 验证与 Tiny/XTiny 契约检查复用分类结果，但不把整个中断分析塞进一个现有内存检查函数。

## 五、风险与预算

### 5.1 最高风险：最终机器栈会计不是 IR 属性统计

K(f)=max({0}∪{3+A(g)+K(g)})；W_j=4+37+F_j+K(j)；R=Σ over 使用的优先级 p [max W_j]。

实施策略：为最终原生指令／已认证展开提供明确栈效果；CFG 数据流计算相对栈偏移、峰值和出口平衡；保存区、普通帧、调用返回帧分别记账；展开发生在分析之后必须提前或绑定精确效果并在发射出口校验；不认识的栈修改不贡献"0B"；顺序兄弟调用取 max 不相加、嵌套沿路径累加；保守相加可作上界但不标真实精确峰值。**DR16 特别门禁**：首期固定 ISR 不额外建动态锚；若实现产生额外 PUSHFP 必须计入 F。

### 5.2 摘要对象风险：覆盖的是最终代码，不是符号清单

| 风险 | 必需测试 |
|---|---|
| 只查 ISR 根，漏主程序另一 TU 动态栈 | ISR 全安全＋另一 TU VLA／stackrestore 仍拒绝 |
| 只查 `STT_FUNC`，漏汇编或无类型代码 | 保留可执行范围出现无摘要字节即拒绝或属认证资产 |
| 一个函数通过整 section 被误判安全 | 同 section 混入未认证代码仍拒绝 |
| 摘要引用使全部代码保活 | 真正死函数可移除，ISR 注册根不可移除 |
| 普通运行时槽被 B 线误禁 | 主程序使用合法静态槽可通过 B；ISR 调用同类槽仍由 A 拒绝 |
| 旧对象／CRT 靠名字获豁免 | 同名普通函数、错误资产版本、改过内容均拒绝 |
| 晚期 libcall 或变换使证明陈旧 | 优化后、机器阶段、对象发射三个出口交叉验证 |

### 5.3 RAM 预算必须向用户展示的实际成本（设计公式算例，非实测保证）

T=align_up(max(D,0x100),16)+16；B=T-1；C=(EDATA_END+1)-T；C≥max(1024,M)+R。

| ISR 组合 | R | 若 M≤1024，最低 C |
|---|---:|---:|
| 一个无调用、无自身帧 ISR | 41B | 1065B |
| 两个不同档位的同类 ISR | 82B | 1106B |
| 四档递增链的同类 ISR | 164B | 1188B |
| I §6.3.4 两级夹具 | 118B | 1142B |

板输入：G12 `EDATA_END=0x0fff`、G144 `EDATA_END=0x3fff`（已核）。默认终止资产单次入口开销 H=4B，不能计 0B。**编译出的保存序列长度、每次入场延迟和抖动目前没有新测量，不给周期承诺**；37B 是 RAM 保存量不是指令字节数。

## 六、O12 落地与真机验收安排

### 6.1 QEMU 资格门禁执行顺序（六步）

①显式选基线（历史 t4 或新 ISR qualification，不用默认可变目录）；②校验资产（绝对路径+内容哈希+源码提交+构建配置；哈希才是内容身份）；③核验配置（machine、参数、设备能力、固件／断言版本）；④先判适用性（每条断言声明所需源、触发方式、是否需要 deferral／周期精确）；⑤再执行（无 icount，轮询＋超时，记录退出原因）；⑥按断言记账（PASS／FAIL／未执行／不支持待真机／基线不匹配分别统计）。

能力矩阵最低项：IRQ0–4 配置／仲裁／嵌套／层级恢复=选定 binary 实测后才 PASS；八槽布局／注册=静态链接能力；宿主控制注入=控制器验证非外设接线；ADC/LVD/PCA 真实触发=当前基线不支持；IP2/IP3 及扩展源=不支持；deferral=不支持／待真机；周期精确=不支持。

### 6.2 必需模型验收分组

Q1 入口与保存（4B 帧、PC／PSW1、37B 全部寄存器、稳定 DR16、SPX 恢复）；Q2 优先级与服务层级（四档、同级 pending、高打断低、高层 RETI 恢复、中间档、无层级泄漏）；Q3 窗口（向量、首保存前后、保存中、固定帧增减、helper 及 ECALL/ERET、恢复中、PSW 恢复后 RETI 前）；Q4 栈（单层、两级精确夹具、四级链、哨兵、长期无漂移）；Q5 负例与默认网（槽冲突、动态 SPX 瞬态、生产拒绝、认证默认入口终止）。

**高打断低必须证明低层已执行后才产生高请求**（两个请求预先 pending、先执行高层不算嵌套）。日志优先写 RAM，停源／关中断后统一输出（避免 UART1 日志自触 TI）。

### 6.3 真机子集与发布标签

**H0 手册与资产审查（不烧录危险负例）**：Sakuna 提交手册版本、页码及逐板结论（槽地址、有效／保留源、优先级与使能映射、四档及嵌套语义、帧 profile、reset／引导交接、NMI 排除、RETI 及控制寄存器写后受理规则）；文档未说明的标未说明，由探针补证。

**H1 G12 首轮可用性子集**：定时器单发／重复、完整现场与 SPX、无槽 ECALL/ERET helper、同级 pending、受控两级嵌套、两级峰值及哨兵、高层返回恢复低层；板支持条件下 INT0／UART1。

**H2 G12 最大链及窗口扩展**：四档递增最大链、逐层返回、长期压力；专门完成手册要求的受理延迟测量。

**H3 G144 独立重复**：同逻辑测试按该板实际数值配置重建；G12 通过不能代填 G144。

发布标签分级：静态工具链通过／QEMU qualification 通过／某板首轮两级子集通过／某板完整四档最大链通过／精确时序已验证或仍待验证。首轮真机不执行：返回帧错配、故意越界、NMI／T0 mode3、未认证高槽、Flash 擦写、`0xFF RSTCFG`。

## 三、批次计划修订

**B02（硬件 profile 冻结）**：①三层集合分开冻结（手册拓扑存在的源/当前板已认证源/应用 may_enable 集）；全表区间 [0xFF0003,0xFF020B) 若全展开须重处理 BOOT 0xFF0100 布局冲突，登记全表≠发射全表；②寄存器语义冻结（四类形态+访问属性+启动写入计划版本入一致性检查）；③**IP3 增"先实测裁决"前置项**（Sakuna 先复核争议出处；使用 IP3 的 profile 冻结前必须真机裁决，探针用已知优先级源对照单独改候选位看仲裁行为；不使用 IP3 的受限 profile 可先冻结但显式排除相关源）；④逐板适用性单独记账（G144 不在系列表单列，须独立确认）。

**B12（CRT 优先级初始化序列）**：关键裁定——**NOP(4) 是"关闭前保留响应空间"的官方范式，不是每次写寄存器后必插四条 NOP 的通用规则**。序列五阶段：受控入口（EA=0、T0m3 从未启动）→完全关闭阶段配置优先级（EA 保持 0，不机械插 NOP(4)——安全依据是受控关闭+NMI 排除，非两次写天然原子）→设备初始化与 pending 处理（T0/T1 硬件自动清零 vs UART/ADC 等软件清零不套同一模板；首期编译器不自动清外设标志）→最后开放（就绪后才写使能+EA；不得以"EA 写完即已受理"为前提）→确需先处理既有事件再关闭的路径（如引入须单独认证"停源→NOP(4)→关闭"序列）。新退出项：最终对象编码中 NOP 数量/位置可核查、控制写与屏障不被优化跨越、序列版本绑定 CRT 资产身份。

**临界区两类序列分别认证**：A 立即保护型（保存原 EA→关→危险操作→**恢复原 EA**；不能宣称关闭前 pending 已消费）；B 停源保留事件机会型（官方 TR0=0;NOP(4);EA=0 模板+项目契约；"事件一定处理完"须另设完成确认，NOP(4) 不是排空证明）。禁止新承诺：四条 NOP 不证明任意两次优先级写原子/SPX 更新安全/通用周期上界。

**EUSB 只写位规则**：禁止普通 IE2 读值作完整使能快照；首期无 USB 显式保持关闭不靠读回证明；后续接口用独占所有权软件影子或显式完整目标状态；不扩大 37B 上下文。

**槽 13**：纳入保留性设计（B02 登记保留用途+禁止误用），不交付兼容中转；槽 14/15 系统内部保留，不作跳板/普通 ISR/备用空间。

**B15 源选择（H1/H2/H3）**：G12 首轮优先普通模式 T0/T1（两级嵌套先在这两源上组织），按板条件加 UART1、传统 INT0/INT1；**禁止用普通 Px 口边沿中断代替触发源**；T0 mode3 禁止。12K128 官方禁用的是第 15 章普通 Px 口边沿中断，**不误扩为传统 INT0/INT1 禁用**；H2 四档链从可配置源组织（不用固定最低的 T2/T3/T4 凑档、不用 T0m3 凑第五档）；同级不可抢占/RETI 恢复/入口帧/SPX 恢复=安全功能放行必验项，不归入"周期以后再测"；G144 独立重建重验。

**十项未定义事项去向**：①周期数→B15 专项测量（样本不自动成最坏上界）；②IP3 位序→B02 复核+使用前真机裁决；③xPTY→永不猜作优先级/仲裁规则，等官方定义；④同级互断/层级表示→B04/H1/H2 验证（QEMU 数组容量不作芯片深度）；⑤查询次序→只报告所测条件，不依赖先后顺序省略保存；⑥EUSB→后续 USB 扩展资格（读恒零不作状态证明）；⑦槽 14/15→永不假定可用，优先请官方澄清；⑧链式 deferral→B15 测有限受控序列（手册无通用上界）；⑨12K128 边沿失败模式→不进 H1/H2，另批勘误调查；⑩Keil 启动内容→"手册未描述"≠"已证明不初始化"，本期无须靠烧录猜。

**其他批次**：B11"完整八槽"→"八位置布局完整、0–6 有效、7 保留"（新增槽 7 注册拒绝）；B14 默认入口测试只用 profile 内合法源；能力矩阵"ADC/LVD/PCA 不支持"拆为"ADC/LVD 当前模型未支持；槽 7/PCA 不属 STC32G 有效源 profile，历史记录单列"。排期影响：B02/B12/B15 增量，**无证据支持压缩原预算**；首期不用的 IP3/USB/DMA/端口扩展调查不暗中绑成首期阻塞。
